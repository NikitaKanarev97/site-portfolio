# T4 — Промежуточные ширины 800–1280 (находки 3 и 6)

Проект: B2B Partner Portal, `D:\Claude-projects\b2b-dssl`. Зависит от T0 и T3.

## Что видел владелец

**Каталог, примерно 1200 px.** Широкая панель фильтров и табличный список товаров
делят ширину так, что таблице остаётся слишком мало: заголовки колонок наслаиваются,
SKU переносится по символу, ссылка «Open product details» рассыпается на короткие
строки, price и availability уезжают вправо, строка выбранных фильтров не помещается
в контейнер.

**Orders, примерно 1200 px.** Таблица шире доступного контейнера: правые колонки
обрезаются, «Next action» и действия «Pay invoice» / «Download invoice» частично
уходят за край, подсвеченные строки выходят за видимую часть карточки.

## Корневая причина (уже найдена, не искать заново)

Раскладка переключается ровно один раз, на 768, и дальше живёт без промежуточного
шага до самого десктопа. Счётчики префиксов в `src`: `md:` 345, `lg:` 50, `xl:` 21,
`2xl:` 0. Пары «боковая панель плюс таблица» — каталог, поиск, XLS-import,
resolution center — раскрываются в полный десктопный вид уже на 768 и держат его
до 1440 без единой поправки.

## Закрыть класс целиком

```bash
grep -rn --include=*.tsx "md:" src/screens src/components | grep -v "lg:" | grep -vE "text-|font-|gap-|p[xytblr]?-|m[xytblr]?-"
grep -rn --include=*.tsx "w-\[280px\]\|w-\[240px\]\|w-\[320px\]\|w-\[360px\]\|basis-\|shrink-0" src/screens
grep -rn --include=*.tsx "aside\|Sidebar\|rail\|Filters" src/screens
```

Первая команда даёт все места, где `md:`-раскладка не уточнена на `lg:`/`xl:` —
это и есть полный список кандидатов. Приоритет: те, где рядом стоит фиксированная
ширина рельса из второй команды.

## Целевой контракт

1. Появляется реальный промежуточный шаг между 768 и 1280. Для каждой пары «рельс плюс таблица» объявляется, на какой ширине рельс сворачивается и на какой таблица переходит во внутренний скроллер.
2. Каталог на промежуточной ширине выбирает одну устойчивую композицию из трёх утверждённых: рельс фильтров раньше уходит в drawer или popover; либо таблица держит минимальную ширину и получает внутренний горизонтальный скролл; либо включается утверждённый карточный режим. Выбор фиксируется решением, а не подбирается по месту.
3. Таблица никогда не сжимается ниже суммы минимумов колонок из T3.
4. Orders: широкая таблица во внутреннем скроллере, «Next action» и ссылки не обрезаются, подсвеченная строка не выходит за карточку.
5. Горизонтальная прокрутка допустима только внутри таблицы, не на документе.
6. Левая вертикаль основной колонки сохраняется: не больше двух уникальных значений `rect.left` у секционных блоков (проба P10).

## Что записать

Выбранную композицию каталога и границы шагов записать в `ds/patterns.md` — что
принято, что отклонено и почему. Если решение меняет D015 «Responsive layout is
mobile-first on one shared scale», добавить новое решение в `ds/DECISIONS.md`
следующим свободным номером и сослаться на него из `ds/foundation.md`.

## Проверка

```
node scripts/adaptive-probe.mjs --probes=P5,P6,P10,P17,P18 \
  --widths=768,800,900,1024,1200,1280 --locales=en,ru \
  --routes=catalog,search-results,orders,xls-import,resolution-center,quick-order,product-details \
  --out=artifacts/adaptive-recheck/t4-widths.json
```

Плюс регресс на краях: те же маршруты на 360 и 1440 — прежние состояния не должны
сломаться.

## Правила

1. Читать только файлы из первой команды грепа, отфильтрованные по второй. Экранные `.md`-спеки — только те, что относятся к изменяемым экранам.
2. Свой харнесс не писать.
3. В чат — не больше 30 строк: таблица «пара рельс+таблица → на какой ширине что происходит», список изменённых файлов, `summary` проб.
4. Один коммит: `fix(layout): между планшетом и десктопом появилась своя ступень`.
