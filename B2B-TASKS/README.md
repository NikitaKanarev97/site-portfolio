# B2B Partner Portal — разбивка визуально-адаптивной постановки на подзадачи

**Источник:** `PROMPT-B2B-visual-responsive-fixes.md` (8 групп находок владельца)
плюс `RECHECK-ADD-COMMON.md` (матрица ширин и каталог проб P1–P18).
**Составлено:** 2026-08-30.

## Что подтверждено в коде

Восемь находок владельца — это пять корневых причин, а не восемь независимых багов.
Проверено грепом по `d:\Claude-projects\b2b-dssl\src`:

| Корневая причина | Признак в коде | Находки владельца |
|---|---|---|
| Фокус не приведён к одному контракту | 37 раз `focus:` против 129 `focus-visible:`; `outline-none` в 20+ компонентах | 1 |
| Нет шкалы слоёв | в `src` всего четыре значения: `z-50` ×11, `z-10` ×7, `z-20` ×3, `z-30` ×1, без токенов и без stacking context у шапки; `sticky` в 15 файлах | 2, 6 (sticky), 8 |
| Нет контракта плотной строки | `DataTable` + 5 компонентов `*Row` + разбор XLS живут на разных сетках | 5, 7, 6 (рассинхрон header/body) |
| Раскладка переключается один раз, на 768 | префиксы: `md:` 345, `lg:` 50, `xl:` 21, `2xl:` 0 — между 768 и 1280 нет ни одного шага | 3, 6 (ширина) |
| Фильтры сверстаны внутри экрана, а не компонентами ДС | чипы и чекбоксы живут прямо в `src/screens/catalog/Catalog.tsx` | 4 |

Список владельца — карта типовых промахов, а не полный перечень. Поэтому каждая
подзадача закрывает **класс целиком**: в каждом промпте есть блок «Закрыть класс»
с готовыми командами `grep`, которые находят все места того же типа.

## Порядок и зависимости

```
T0 харнесс  ──┬─→ T1 фокус ─────────────┐
              ├─→ T2 шапка и слои ──────┤
              └─→ T3 плотная строка ─→ T4 промежуточные ширины ─→ T5 фильтры ─→ T6 приёмка
```

- **T0 обязателен первым.** Без него каждый следующий чат заново пишет Playwright-харнесс — это и есть главный пожиратель токенов.
- **T1, T2, T3 не конфликтуют по файлам** — их можно вести параллельно в отдельных чатах.
- **T4 после T3** (нужны минимальные ширины колонок из контракта строки).
- **T5 после T4** (T4 решает, где рельс фильтров уходит в drawer; T5 чинит внутренности контролов).
- **T6 последним** — единственный полный прогон матрицы.

Один чат = одна подзадача = один коммит. Не смешивать.

## Правила экономии токенов (продублированы в каждом промпте)

1. Читать только файлы, названные в промпте. Не перечитывать `ds/` целиком — нужные строки контракта процитированы в промпте.
2. Не писать новый харнесс: `node scripts/adaptive-probe.mjs` из T0.
3. Не гонять полную матрицу в каждой подзадаче. Только маршруты, ширины и пробы, названные в промпте. Полный прогон один раз — в T6.
4. Скриншот снимать только под подтверждённый провал пробы, в файл, не в чат.
5. Доказательства — в JSON. В чат — не больше 30 строк: что было, что стало, какие пробы прошли.
6. Не трогать бизнес-логику, данные, маршруты и `i18n`. Не трогать файлы вне заявленного скоупа.
