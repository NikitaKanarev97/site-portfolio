# T6 — Приёмка (делать последним)

Проект: B2B Partner Portal, `D:\Claude-projects\b2b-dssl`. Зависит от T0–T5.

## Задача

Один полный прогон вместо шести частичных, сведение результата и закрытие
постановки владельца. Чинить здесь можно только то, что вскрыл прогон, и только
точечно; крупная находка возвращается в свою подзадачу отдельным чатом.

## Прогон

```
node scripts/adaptive-probe.mjs --out=artifacts/adaptive-recheck/t6-full.json
```

Значения по умолчанию: все маршруты реестра, ширины 360, 390, 480, 768, 800, 900,
1024, 1200, 1280, 1440, локали en и ru, пробы P1–P18.

## Критерии приёмки владельца

Для Catalog, Orders, XLS import / parse result и экранов с Quantity и Counterparty,
на каждой ширине, в обеих локалях:

- нет document horizontal overflow;
- нет наложения текста и колонок;
- ничего не проходит поверх AppHeader;
- все данные и действия на месте, ничего не выброшено ради помещаемости;
- клик мышью не даёт системной синей рамки;
- с клавиатуры виден доступный `:focus-visible`;
- нет обрезанных badges, links и CTA;
- внутренние скроллеры только там, где заявлены;
- console и page errors — ноль.

## Что записать

1. `artifacts/adaptive-qa/findings.md` — заменить строку «No findings» на реальный итог: восемь групп владельца, для каждой корневая причина, подзадача, в которой закрыта, и проба, которая это доказывает.
2. `artifacts/adaptive-recheck/t6-full.json` — доказательство прогона.
3. Короткая сводка: единый контракт фокуса, шкала слоёв и контракт таблицы — по абзацу на каждый.

## Правила

1. Читать только JSON-отчёты подзадач и `findings.md`. Исходники — только под конкретный провал.
2. В чат — не больше 40 строк: таблица «находка владельца → корневая причина → где закрыта → проба», результат гейтов, остаток открытых вопросов.
3. Один коммит: `test(qa): постановка владельца закрыта и доказана прогоном`.
