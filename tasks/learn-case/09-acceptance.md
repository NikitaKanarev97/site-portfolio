# 09 — Финальная сборка и приёмка кейса

Зависимость: 08 готов. Работай по `STATE.md`. Результат: законченный локальный кейс EN/RU с работающими демо и доказанной проверкой.

## Мини-задачи

1. Прочитай актуальную передачу, `ds/screens/case-learn.md`, EN/RU объекты Learn, общие шаблоны кейса и обязательные документы ДС портфолио. Используй готовую композицию сайта. Не начинай заново исследование или написание кейса.
2. Выполни `npm run build` ПОСЛЕ появления всех изображений: MediaFrame определяет размеры на сборке. Подними/обнови preview. Проверь обложку, «до/после», блоки решений, zoom изображений и подписи на обеих страницах `/work/learn/`, `/ru/work/learn/` на 1440 и 375.
3. Проверь карточку Learn на главной EN/RU, переключение языка, следующий кейс, обе ссылки в шапке и ссылку на прототип. Проверь sitemap, hreflang, OG и соответствие языка новых кадров.
4. Точечно выровняй подписи с реальными экранами. Позиционирование по learn/PROJECT-CONTEXT.md: реальная рабочая задача в DSSL / TRASSIR, переосмысленная автором после ухода из компании. Нынешний прототип не выдавать за выпущенный тогда редизайн или текущий сайт; исходный проект не называть учебным/вымышленным или инициативой без заказа. Не придумывать метрики, точные сроки и распределение функций между версиями. Агентская QA и синтетические интервью относятся к нынешней итерации. Архивный русский каталог подписывать как исходную платформу, новые экраны — как нынешний подход автора.
5. Выполни `npm run check`, `npm run check:css` после build, `npm run verify:learn` и `node scripts/verify-portfolio-locales.mjs`. Перед запуском проверь origin preview в скриптах/переменных. Ошибки новых скриптов исправляй без ослабления проверяемого поведения; учитывай lazy loading при проверке изображений.
6. Исправь дефекты этого кейса и интеграции. После изменения исходников/медиа пересобери соответствующий результат и повтори только затронутые проверки; общий регресс не повторяй без причины. Если найдётся большая отдельная проблема, зафиксируй её точно и оставь этап частичным.
7. Уточни фактический статус в README и карте кейса, сохрани короткий `reports/09.md`, обнови STATE.md. Проверь diff, чтобы не включить посторонние изменения. Если менялись tokens/motion портфолио, проверь побайтовую идентичность их ds/src зеркал.

## Критерий завершения

Обе страницы кейса собраны; все кадры и подписи корректны; сервис и лендинг работают на языке портфолио, включая глубокий вход/reload; обязательные проверки проходят. Дай пользователю локальные ссылки и краткий результат. Не заявляй публикацию: автоматические commit/push/deploy в этот этап не входят.
