# 06 — Сервис и лендинг внутри портфолио

Зависимость: 05 готов. Работай по `STATE.md`. Результат: оба готовых приложения доступны локально из портфолио.

## Мини-задачи

1. Прочитай `scripts/sync-learn-prototypes.mjs` в Site-portfolio и `D:/Claude-projects/learn/landing/app/LOCALIZATION.md`. Лендинг уже локализован. Проверь настройки base, ссылок и границы generated-каталогов перед заменой экспортов.
2. Выполни из портфолио `npm run sync:learn`. При необходимости исправь существующий скрипт. Экспорты: `public/prototypes/learn/`, `public/prototypes/learn-landing/`, манифест маршрутов. Не копируй fixtures в public.
3. Проверь, что экспорт содержит HTML-входы для фиксированных и параметризованных маршрутов продукта, включая material, trajectory, player. Адресная перезагрузка должна работать на статическом хостинге. Проверь физические файлы, а не только dev-сервер с SPA fallback.
4. Выполни `npm run build` и запусти preview портфолио, по умолчанию `http://127.0.0.1:4322`. Отсутствие будущих медиа кейса сейчас ожидаемо: это промежуточная сборка для доступа к демо.
5. В обеих локалях проверь `/prototypes/learn/home?lang=en|ru`, несколько глубоких страниц, `/prototypes/learn-landing/?lang=en|ru`, ссылки лендинг → сервис, reload и загрузку assets. EN `/en/` лендинга должен работать и без JS. Проверь desktop/mobile, не повторяя всю прежнюю матрицу лендинга.
6. Подтверди: обычный `npm run build` портфолио использует сохранённые экспорты, не запускает сборку соседнего Learn и не требует его исходников. Не удаляй соседнюю папку ради проверки.

## Приёмка и остановка

Демо доступны внутри портфолио на правильном языке, deep links и assets исправны. Запиши команды, URL preview, расположение экспортов и результат в STATE.md / `reports/06.md`. `verify:learn` со всеми изображениями запускать в 09. Следующий этап — 07.
