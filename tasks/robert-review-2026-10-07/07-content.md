# 07 — Авторские проекты без запрещённых статусных меток

Прямая новая постановка владельца: «никаких упоминаний концепт и так далее; нигде не пишем концепт; написать правило и проверить, чтобы на сайте такого не было». Владелец попросил отдельный чат для исправления уже появившихся случаев.

Сначала прочитать корневые CONTENT-RULES.md, CLAUDE.md, PROJECT.md и README.md этого пакета. Правило CONTENT-RULES.md заменяет прежнее требование сохранять Concept. Технические инварианты ДС сохраняются; визуальную перестройку чужих пакетов не повторять.

## Задача

1. Сделать инвентарь публичных упоминаний в EN/RU. Уже подтверждены случаи в src/copy/featured-work.ts, src/copy/og.ts, src/copy/cases/vet-clinic.ts, src/copy/cases/pawly.ts и RU-парах. Часть строк находится в старых вариантах рассказа, часть — в действующих cover/facts/outcome. Проследить реальный renderer и вывод, не ограничиваться одним Home.
2. Переписать публичные тексты как рассказ об авторских проектах: задача, работа, решения, показанный результат. Удалить плашки Concept/концепт и смысловые заменители из заголовков, подпунктов, фактов, caption, note/outcome, title/description, alt/aria, social/OG. Не просто вырезать слово из сломанной фразы. Не придумывать запуск, интервью, заказчика, метрики и даты.
3. Проверить публичные PDF/CV и опубликованные OG/картинки: запрещённый статус может быть встроен в растровое изображение. Исходники OG сейчас редактирует пакет 01 — дождаться его стабильного результата, затем исправить найденные публичные тексты. Продуктовые UI-пиксели сохранять; при необходимости изменения изображения применять соответствующий skill/tool, а не рисовать новый UI.
4. Добавить маленькую повторяемую content-проверку (например scripts/check-public-content.mjs) для актуальных публичных текстов/собранных штатных HTML. Нулевой результат по запрещённым статусам должен проверяться автоматически, с понятными file/route при нарушении. Технический motion-concept.md, закрытые fixtures/архивы и внутренние keys не считать публичным label. Не вводить широкие исключения, скрывающие реальную страницу.
5. После завершения визуальных пакетов повторить сквозную проверку сборки и реальных EN/RU маршрутов, включая метаданные. Проверить, что параллельные чаты не вернули подписи. npm run check/build и content-check должны относиться к финальному состоянию. Краткий браузерный просмотр Home, Vet/Pawly и всех остальных страниц нужен для вывода о сайте, исходный rg не заменяет его.

## Владение и параллельная работа

Ты не один в кодовой базе. Пакеты 01–06 работают в одном checkout; не отменять их правки. Свободные для твоей редакционной правки файлы: src/copy/featured-work.ts, src/copy/cases/*, src/copy/ru/cases/* и прочие публичные copy, не закреплённые за текущим владельцем; новые scripts/check-public-content.mjs и только свои reports/07-*.

src/copy/home.ts и ru/home.ts заняты чатом 02; site.ts пары — 06; case-art.ts — 04; OG renderer и общая ДС/зависимости — 01. Сначала проверить незанятые файлы и подготовить точечные исправления остальных. Изменять занятые файлы после результата соответствующего владельца, сохранять его финальные изменения. Следить за отчётами reports/01–06-result.md и компактными wait_threads по ids в README; не отправлять сообщения другим чатам без отдельной авторизации пользователя. При необходимости package.json script добавить после стабильной передачи чата 01. Не начинать заново все шесть пакетов и не редактировать их source-компоненты ради внешнего вида.

Встреченное в README/reports старое «сохранить Concept» считается отменённым новой прямой постановкой. Если внутренний отчёт содержит такое требование для будущего публичного вывода, исправить активную инструкцию либо явно отметить её замену в 07-result. Исторические исследования уничтожать не нужно.

Dev порт 4407. Для build/dev использовать собственные служебные каталоги Astro при необходимости: соседние серверы уже сталкивались на shared cache. Не останавливать чужие процессы. Не делать git add -A, reset/clean, общий commit/push/deploy. Новые факты не изобретать; задача — редакционная подача и её проверка.
