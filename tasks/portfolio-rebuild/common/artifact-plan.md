## A-IA / Portal / после фактов

Тезис: два входа в закупку работают с одной спецификацией, а заказ продолжает её историю.

- Эталон: **HA-MAP-01**, `references/ha-screen-map.png`.
- Данные: `D:/Claude-projects/b2b-dssl/ia/sitemap.md`, текущие 16 MVP-экранов; `ds/DECISIONS.md` D006–D010. Редакционная выборка текущей пересборки, не историческая карта отгрузки.
- Состав: Dashboard (1), XlsImport (2), QuickOrder (3), ResolutionCenter (4), Cart (5), FulfillmentPlans (6), OrderDetails (7). Login/контрагент, recovery, глобальные функции и промежуточные Checkout/OrderSuccess намеренно вне компактного scope. Номера — локальные ссылки на названные экраны, не их исходные номера в sitemap.
- Функции ResolutionCenter: выбрать соответствие; исправить исходную строку. У Cart: принять коммерческую дельту. Группы Intake и Specification подписаны; связи без стрелок показывают общую сущность/иерархию, не время.
- Desktop: три зоны слева направо, два intake рядом вертикально, один resolver; дерево без пересечения текста. Mobile: та же выборка и все связи, вертикальные уровни, без уменьшения текста. Геометрия EN/RU общая.
- Сохраняем: светлое ровное поле, белые плашки, тонкая гребёнка, пунктир функциональной группы, квадратный синий номер внутри правого верхнего угла. Адаптация: свой scope, компактный лист вместо всей IA; порядок чтения вниз на телефоне.
- EN/RU подпись: «Selected MVP screens · editorial map» / «Выборка экранов MVP · редакционная карта». Summary объясняет два intake и общую спецификацию.
- Все узлы и связи видны в статике; draw только однократное пояснение связей. Новые данные: `src/data/diagrams/common/portal-map.ts`.

## A-FLOW / Portal / вслед за IA

Тезис: импорт не разрешает неоднозначность за покупателя; коммерческое изменение проверяется отдельно в корзине.

- Эталон: **HA-FLOW-01**, `references/ha-user-flow.png`.
- Данные: `ia/flows/xls-to-order.mmd`, D007–D010, актуальные ResolutionRow и FileUpload. Редакционная схема текущего MVP на synthetic fixture.
- Точный состав: «Upload XLS» (start + черта) → «Read lines» (screen) → «Unresolved lines?» (decision). Yes → «Choose / correct» (input), возврат к условию. No → «Cart» → «Commercial change?» (decision). Yes → «Accept / resolve» (input), возврат к Cart. No → «Choose plan» → «Order created» (screen). Checkout как действие внутри завершения; полный access-префикс опущен и не выдаётся за весь flow.
- Desktop: верхний путь слева направо, две ветви решения ниже, возвраты ортогонально. Mobile: вертикальный путь; оба условия, обе ветви и возвраты сохранены. Отдельная геометрия тем же renderer, node/edge IDs совпадают.
- Сохраняем: шапку с линией, старт без овала, белые шаги, контурные ромбы/параллелограммы, yes/no на исходящих связях, открытые стрелки. Свои короткие EN/RU подписи; не копируем ошибки текста донора.
- Статика содержит всю логику, reduce/no-JS не теряют ветви. Новые данные: `src/data/diagrams/common/portal-flow.ts`.

## A-DS / Portal / реальный specimen

Тезис: идентичность, импорт и коммерческая доступность имеют разные состояния в настоящем UI.

- Эталон: **HA-DS-01**, `references/ha-component-library.png`.
- Источник: accepted каталог b2b-dssl, `storybook-static` от 14.09.2026 (после refinement closeout 11.09), сверка с текущими `src/components/*/*.stories.tsx`, `src/tokens/{primitives,semantics,typography}.css`. Capture `iframe.html?id=components-domain-…`; реальные компоненты, без импорта React runtime в портфолио.
- Foundation: Inter; 6 ролей: Page heading 32/42 600, Section 24/36 600, Row 18/27 600, Body 16/24 400, Status 12/18 600, Data 11/16 500 tabular. Четыре колонки: стиль / применение / метрики / живой образец. 10 свотчей: primary #2563eb; white #ffffff; sheet #fafbfc; ground #e7eaf0; ink #0f172a; muted #475569; success #166534; warning #92400e; error #b91c1c; info #0369a1. Значения — данные продукта, не переопределение портфолио.
- 4 настоящих семейства: FileUpload empty/complete/error (processing сохранён в полном каталоге, временное состояние вне рассказа); ResolutionRow ambiguous/missing/error/confirmed-from-ambiguous (exact/changed вынесены в каталог; выборка не именуется полной матрицей); Availability verified/stale/not-confirmed; QuantityStepper default/at-minimum/disabled. Никаких invented variants. Все состояния каждого набора вертикально, подписи рядом, реальные внутренние размеры и actions сохранены.
- Desktop: foundation примерно 35%, specimens 65%; ResolutionRow во всю ширину правой части, остальные в двух колонках; тонкий служебный синий пунктир вокруг семейства. Состояния ResolutionRow снимаются целой карточкой на узкой продуктовой раскладке, чтобы список полей читался в этой композиции; это явно подписанная адаптация масштаба, не desktop-таблица, сжатая в колонку.
- Mobile: последовательные материалы foundation → импорт/разрешение → доступность/количество. Показываем реальные адаптивные DOM-кадры при 288 CSS px (для колонки 360 с полями), DPR 2. Узкая версия сохраняет все выбранные состояния; лист не скейлится целиком. EN/RU обрамление, исходный UI EN по D001 каталога; перевод UI внутри кадров не имитируем.
- Сохраняем: таблицу с четырьмя колонками на desktop, палитру ниже, большую правую область, вертикальные состояния и настоящее применение. Адаптация: 4 семейства вместо всей телеком-библиотеки, синий пунктир вместо фиолетового, карточки текущего продукта, 10 свотчей.
- Соседний кадр применения: существующий настоящий `/media/case-dssl/` ResolutionCenter (проверить доступный filename при инвентаре), новый capture лишь при отсутствии подходящего материала.
- Caption: «Accepted domain components · selected states · synthetic data» / «Принятые доменные компоненты · выбранные состояния · демоданные». Alt перечисляет существенные поля/действия. Статика и конечный кадр движения одинаковые.
- Common composition: новый тонкий `CaseSpecimen` только как сборка CasePlate + CaseScreen + native foundation table. `Diagram library` рисует условные контролы и потому не подходит actual specimens. Нотация продукта не рисуется заново. До реализации описать в `ds/components.md`.

## Уточнение после capture и визуальной сверки · 04.10.2026

Source catalog подтверждает: Missing → **Request item**, Error → **Fix line** при нечитаемом quantity, Confirmed хранит **was Ambiguous** и Undo. Подписи и alt приведены к этим действиям; ошибки сохранения не выдумываются. QuantityStepper имеет реальную CSS-ширину 138 px (старый комментарий 116 не совпадает с DOM); Availability сохраняет свои 150/164/126 px.

В итоговом A-DS ResolutionRow и FileUpload стоят в двух равных колонках справа, без `wide`: полная широкая строка давала слишком разреженный лист. Обе группы используют настоящие адаптивные кадры 288 CSS px; дополнительно архивированы 480 CSS px. Foundation остаётся 35% на 1440, на tablet занимает всю верхнюю полосу, на mobile строки становятся записями с полноширинным живым образцом. Палитра сохраняется ниже. Масштаб small controls ограничен `ShotItem.nativeWidth`, целый экран применения — `/media/case-dssl/polish-after-resolution.webp`.

A-FLOW mobile занимает 29 клеток основного поля; вместе с полями renderer помещается в доступные 280 px при окне 360, кегль и ветви сохранены. Номер A-MAP занимает квадрат внутри угла; renderer резервирует место для него в auto-width названия. Фактические кадры и сравнительные листы перечисляются в report.md.

При последней сверке A-DS рамки семейств выровнены по началу собственной высоты. FileUpload и QuantityStepper не получают пустую область от более высокого соседа; порядок, размеры настоящих компонентов и высота общей строки материала сохраняются.
