## Art direction · 03.10.2026 — актуальная постановка Agent Ops

### Доводка · checkpoint

`CaseSteps focus composition=checkpoint`: один тёмный рабочий стол, четыре пространственных состояния. Причины и workspace — широкий горизонтальный кадр; переписка — справа от текста у вертикального рубежа; согласование — справа от крупного двухштрихового знака Human review. Знак — редакционный образ остановки, не контрол продукта. Каждый материал целый, без дублей, с сохранённым source padding. На mobile / коротком окне / reduce / no-JS — последовательное чтение; знак остаётся перед последним согласованием. Поля тёмного стола симметричны, асимметрия принадлежит содержимому. Opt-in только пилота.

Хореография: обзор немного отступает по масштабу перед сменой контекста; переписка входит к рубежу; при последнем обмене штрихи раскрываются в полный стоп, затем карточка приходит к месту решения. В остановленном скролле виден один целый материал при полной непрозрачности. Обратный скролл обращает движение. Без fade ghosts, обрезки интерфейса и движения фона. Художественная приёмка принадлежит владельцу.

Замысел: «Между обещанием и деньгами появляется человек». Этот раздел заменяет ограничения S3 на неизменную пару proof и wide/wide/split для пилота; остальные фактические и системные правила остаются.

Раскадровка: чистое крупное Agent Ops; слева точное сообщение, справа сумма, между ними вертикальный шлюз Human review. Панели сходятся с двух сторон и останавливаются у шлюза. Далее целые кластеры занимают широкое поле; тот же центр становится рабочим контекстом; контекст уступает место целой переписке с неподкреплённым обещанием; центр расширяется в карточку согласования с обоими действиями. Последующий довод — целая трасса, затем принятый прототип.

Переносимые варианты: `CaseCover proof layout=interlock` с отдельно заданным текстом шлюза; `CaseSteps variant=focus` с независимыми материалами. Они включены только в Agent Ops. Пропорции сохраняются. Focus закрепляет единую сцену, а не предыдущий li; старые режимы доступны другим композициям. От 1024 и достаточной высоты — конечная последовательность состояний, на коротком desktop / mobile / reduce / no-JS — нативное чтение. На телефоне шлюз горизонтальный, панели идут по очереди во всю ширину. Никакого бесконечного цикла или перехвата wheel.

## S3: переносимая система · 03.10.2026

Поправка полей по обратной связи владельца: `clusters` и `transcript` — внутренние прозрачные блоки, а не самостоятельные карточки. При съёмке им сохраняется поле исходного `surface-page`: симметричный `space-3xl` (32 px) на desktop и `space-2xl` (24 px) на mobile из токенов прототипа. Содержимое и ширина самого блока не меняются; снимается весь блок вместе с полем. Это внутренний отступ тёмного материала, дополнительно к внешней светлой CasePlate. Evidence и approval уже имеют собственные внутренние поля — дополнительное обрамление им не нужно.

S2 закрыт владельцем. S3 закрепляет композицию и техническое поведение пилота; записи S1/S2 и исходная карта ниже сохраняют историю. Это историческое состояние S3; для обложки и центральной сцены приоритет у Art direction выше. Перенос опубликованных кейсов, RU и главной — отдельная работа. Художественная приёмка владельца не подменяется машинными проверками.

### Выбор обложки

| Вариант | Когда выбирать | Материал и отказ |
|---|---|---|
| `proof` | Тезис доказывается одной панелью или связанной парой последствий | Целый реальный DOM-узел; `panels` для независимых кадров, `shot` для общей композиции. У каждого кадра свой `srcNarrow`. Статика совпадает с конечным состоянием движения |
| `screen` | Важны рабочий контекст, устройство продукта или связка устройств | Один целый экран, screen-detail рядом, phones для мобильного продукта. Деталь не дублирует UI поверх общего экрана. На телефоне — собственная раскладка |
| `video` | Изменение во времени доказывает то, чего не показывает статичный кадр | Реальные экраны, читаемый постер, MP4 + WebM, видимая пауза. Чистая зона под текст; ни UI, ни кнопки не режутся под декоративную рамку. Без JS/reduce — постер; при ошибке WebM попытка MP4, затем постер |

Для Agent Ops закреплён `proof`: сумма и точное сообщение стоят до одобрения. Вступление — один конечный каскад, 1 с / power3.out / y 24 px / шаг 120 мс, акцент второго кадра x 12 px. Жест чтения дожимает вступление. Тезис остаётся editorial, переход — 1 с editorial. Амплитуды и timing меняют только в `ds/motion.js` с побайтовым зеркалом.

**3D-пререндер не требуется для текущей обложки.** Это возможное отдельное производство, если понадобится показать причинную связь в движении. Вход — реальные экраны как текстуры, выход — ролик с чистой зоной текста и статичным proof/poster fallback. Генерировать интерфейс или блокировать готовую страницу ожиданием фильма нельзя.

### Ритм и pin

Модули выбираются по доводу, не ради десяти заполненных блоков. Целевой видимый текст — 300–450 слов, абзац ≤35, подпись ≤12. Оценки помечаются у каждого числа; результат не заменяется расчётной экономией. В пилоте сохраняются причины / контекст / согласование: wide / wide / split, затем трасса и принятый прототип.

| Условие | Поведение |
|---|---|
| Без JS, reduce, ширина ниже `bp-xl` | Естественный список; текст перед кадром, своя пропорция, без обязательного пустого 100svh |
| Шаг помещается в `innerHeight − 2 × inset` | Pin сверху с inset 32 px |
| Шаг выше доступного окна | Читается целиком; pin снизу только после прохождения низа |
| Последний шаг | Не закрепляется; ведёт к следующему доводу |
| Следующий шаг входит | Занимает место предыдущего; уход −24 px / scrub .25, pinSpacing=false |
| Обложка помещается и за ней `CaseSheet` | Sticky и наезд листа; затем обложка скрыта до обратного скролла |
| Высокая обложка или самостоятельный образец /kit | Поток; sheet-сцена не создаётся и не сбрасывается на каждом кадре |

Gap списка — `flow-block`, сохраняется при обёртках GSAP. Не выравнивать разные панели кропом, scale или искусственной высотой. Для короткого окна и resize выбор pin-позиции пересчитывается.

### Переход и жизненный цикл

- `transitionKey` принадлежит следующей ссылке и входной обложке её назначения. На одной странице ключ не повторяется; в snapshot включается только выбранная пара. Текущие совместимые ключи: `case-agent`, `case-portal`; новую тему сначала добавляют в motion CSS общего слоя.
- Обычная ссылка обязательна. Колесо, End/Home, быстрый скролл не открывают следующий кейс. Back восстанавливает позицию; возвращённая страница остаётся читаемой без повторного вступления.
- Исполнитель — `animations.js`, регистрация через `withMotionPreference()`. Компоненты содержат структуру и данные. SplitText `autoSplit` пересчитывает строки; маски с bleed сохраняют выступающие части букв.
- На reduce / уходе: revert контекстов, SplitText, responsive pin и sheet; снять listeners и observer, остановить видео. На новой странице создаётся ровно один комплект сцен.
- Marquee играет только в окне и видимой вкладке. Ручная пауза сохраняется при уходе из окна и смене reduce/full. Фокус и mouse hover удерживают паузу даже при повторном входе блока; touch не включает hover.
- Видео играет только пока обложка видна и не закрыта листом. Смена reduce останавливает автозапуск; читатель может явно запустить видео кнопкой. Ручная пауза не сбрасывается сменой предпочтения. Без JS кнопка скрыта.

## S2: движение · 03.10.2026

Обложка proof теперь принимает две независимые целые панели того же `ConsequencePreview`: payout → message, конечная композиция совпадает с S1. На телефоне оба кадра идут естественным столбиком. Pin-swap от bp-xl сохраняет wide / wide / split и исходные пропорции: причины закрепляются сверху, высокий контекст сначала прокручивается до конца и закрепляется снизу, согласование занимает его место. До bp-xl, без JS и в reduce остаётся нативный список. PinSpacing не добавляет высоту. Сетка списка сохраняет gap при технических pin-обёртках.

Sheet удерживает только помещающуюся обложку; высокая остаётся в потоке. После листа обложка не показывается снова под следующим кейсом. Переход по обычной ссылке проверяется на `/preview/agent-ops-pilot/` ↔ `/preview/partner-portal-pilot/`; Partner Portal — минимальный закрытый образец из существующих реальных материалов. Общие ключи `case-agent` / `case-portal` включаются только для выбранной пары, без wheel-перехвата. Параметры и fallback — `ds/motion-concept.md` §3. Реальные EN/RU маршруты ожидают отдельного переноса; шаблон не заморожен.

## 2. Модули

Одиннадцать модулей из DoD этапа плюс два служебных (`CasePlate`, `CaseShot`), на которых держатся правила плашек и кадра. Все в `src/components/`, анимаций не пишут.

| Модуль | Что это | Пропы (из `story.*`) |
|---|---|---|
| `CaseCover` | обложка, два варианта, §4 | `variant: 'video' \| 'screen'`, `theme`, `title`, `outcome`, `media` |
| `CaseSheet` | белый лист, наезжает на закреплённую обложку | слот |
| `CaseFacts` | строка фактов вверху листа: 4–6 пар «метка / значение», последняя может быть ссылкой на прототип | `items: { term, value, href? }[]` |
| `CaseThesis` | метка + тезис ≤ 60 знаков + абзац ≤ 35 слов | `label`, `thesis`, `body?` |
| `CaseNumbers` | цепочка чисел со стрелками (блок 02): `1 770 → 71 → 2,4 h` | `items: { value, caption }[]` |
| `CasePlate` | плашка: симметричные поля, одна светлая, тёмная только у тёмного продукта | `tone: 'light' \| 'dark'`, слот |

| `CaseCallout` | один элемент крупно, нумерованные выноски линиями к подписям сбоку | `tone: 'note' \| 'issue'`, `src`, `marks: { x, y, text }[]`, `caption` |

Остальные одиннадцать — новые строки в `ds/components.md` (контракт §«Нет компонента»: композицией существующих они не собираются — у каждого своя геометрия или своё поведение).

## 4. Обложка — два варианта

Цвет кейса живёт **только здесь и в `CaseNext`.** Токены — существующие `surface-cover-*`. Тон текста поверх: тёмные холсты (agent, learn) → `text-on-inverse`, светлые (portal, vet, pawly) → `text-default`; контраст проверен: белый на graphite-800 13.1:1, на navy-800 11.3:1; ink на blue-100 13.8:1, на sage-100 14.0:1, на sand-100 13.5:1.

**Это снимает правило 09.09.2026 «текст поверх цветных холстов не ставится»** (`foundation.md`, шапка). Тогда холст был фоном превью на главной, и подпись стояла под ним. В новом шаблоне название на цвете — сам приём HA. Текст поверх **скриншота** по-прежнему запрещён: название стоит на чистом цвете, кадр — ниже или под ним.

**Общее у обоих.** Обложка — `position: sticky; top: 0`, высота `100svh` (ниже `bp-md` у варианта `screen` — по содержимому, §9). Лист `CaseSheet` идёт в потоке следом с `z-index` выше и непрозрачным фоном — при прокрутке он наезжает на обложку нативным скроллом, без перехвата и без JS. Навбар остаётся в потоке над обложкой (перекрашивание навбара поверх обложки, как `-is-white` у HA, — вопрос этапа 3).

### 4.1 «Видео» — только Agent Ops

Как Telecom Tools у HA: ролик этапа 4 на весь холст (`object-fit: cover`, фон ролика совпадает с `surface-cover-agent`), поверх в нижнем левом углу огромное название `ds-display-7xl` и строка итога `ds-heading-xl`, до 25 слов.

- `<video muted playsinline loop preload="auto" poster>` + WebM/MP4; это первый экран, поэтому `preload="auto"` здесь оправдан, в отличие от клипов `MediaFrame`.
- Кнопка паузы видима всегда (`WCAG 2.2.2`). Ролик играет, пока обложка в окне, и встаёт вне его: запуск при загрузке Chrome гасил у обложки ниже сгиба (найдено на `/kit`). Ручная пауза держится до следующего нажатия.
- Под названием ролик уходит в цвет кейса градиентом на нижнюю половину — страховка, если кадр ролика зайдёт под название. Это продолжение поля обложки, не подсветка поверх экрана.
- `prefers-reduced-motion` — постер, ролик не стартует.
- Название не перекрывает экран устройства: ролик снимается с пустой нижней третью (требование к этапу 4).
- До этапа 4 на `/kit` вместо ролика стоит постер-заглушка из имеющегося кадра Agent Ops.

### 4.2 «Экран на цвете кейса» — остальные четыре

Сверху на цвете — название `ds-display-6xl` и строка итога; ниже кадр продукта **на самом цвете** (цвет здесь и есть плашка). Кадр целиком внутри обложки: ряд экранов вписан в остаток высоты под названием через контейнерные единицы, поля по горизонтали симметричны. **Выход за край вниз, заложенный в черновик, снят при вёрстке:** низ кадра под листом не виден никогда, то есть кадр резался бы посреди интерфейса — ровно то, что запрещает правило 2.

Подача у каждого своя — это часть замысла, а не разнобой. Вариант задаётся `media.layout`:

| `layout` | Кому | Что в кадре |
|---|---|---|
| `screen` | Partner Portal, Learn | один десктопный экран целиком, крупно |
| `screen-detail` | Vet Clinic | экран целиком и один ключевой фрагмент рядом, **не поверх** (правило 1) |
| `phones` | Pawly | 2–3 телефона группой, без корпуса; либо фото «в руке» (`media.photo`) — выбирается на этапе 11 |

Никаких увеличенных копий поверх экрана (правило 1), кадр по стандарту §6.

## 5. Правила плашек

| Правило | Как держится |
|---|---|
| Поля симметричны и из токенов | `CasePlate` — `padding` одним значением на все четыре стороны: `space-4` (16) < `bp-md`, `space-12` (48) от `bp-md`, `space-16` (64) от `bp-lg`. Внутреннее поле компонента — прямой `space-*` по контракту §4. Содержимое центрировано. |
| Одна светлая плашка для экранов | новый смысловой токен `surface-plate` → `gray-100`. Других светлых плашек нет: голубых, бежевых и «как получилось» больше не бывает. |
| Тёмная — только у тёмного продукта | `surface-plate-dark` → `gray-950`, `story.plate: 'dark'` — у Agent Ops; во всех его кадрах одна и та же. |
| Цвет кейса — только обложка и переход | `surface-cover-*` читают только `CaseCover` и `CaseNext`. `CasePlate` их не принимает вовсе. |
| Диаграмма на плашке | внутри `CasePlate` поле схемы приравнено к плашке (`--diagram-field: var(--surface-plate)`), чтобы не было плашки в плашке; тёмная плашка совпадает с тёмным полем схемы (`gray-950`). |
| Скругление | `radius-lg` от `bp-md`, `radius-md` ниже — как у `MediaFrame wide`. |
| Ничего не режется краем | дочерний элемент выходит за плашку только с классом `-bleed`. В шаблоне таких выходов нет; класс остаётся механизмом для осознанного исключения, и `harmony-check` его уважает. |
| Мягкий вид | экран на плашке: `radius-md`, `shadow-md`, волосяная `border-default`; без цветных подсветок поверх скриншота. |

## 6. Стандарт кадра

- Десктоп **1440 × 900 при 2x** (файл 2880 × 1800, 16:10 = `ratio-screen`), телефон **390 × 844 при 3x** (1170 × 2532).
- Кадр — экран целиком или блок целиком. Без полос прокрутки, подвала сайта продукта, панели плеера.
- `CaseShot layout=pair`: десктоп и телефон **одного экрана в одном кадре**, одной высоты, телефон справа. Не двумя кадрами подряд (правило 13).
- `layout=phones`: 2–3 телефона одной высоты в ряд.
- Один масштаб на кадр (правило 4): в паре телефон и десктоп одной высоты, крупный фрагмент — только в `CaseCallout`, отдельным кадром.
- Подпись под плашкой (на белом листе, не на плашке — `text-muted` на `gray-100` дал бы 4.46:1): одна строка, ≤ 12 слов, `ds-body-sm` обычным шрифтом, `text-muted`. Моно — только метки и числа.
- Видео взаимодействия — тот же `MediaFrame video`, внутри `CasePlate`.

## 7. Текст и вертикаль

**Типографика — четыре уровня (правило 8):**

| Уровень | Роль | Где |
|---|---|---|
| метка | `ds-meta-xs` (моно, капс, 12) | `CaseThesis`, `CaseFacts`, `CaseNext`, номер шага |
| тезис | `ds-heading-4xl` (48 → 32 < `bp-md`), `text-wrap: balance` | `CaseThesis`, тезис шага |
| абзац | `ds-body-lg` (18), `text-wrap: pretty` | тело модуля |
| подпись | `ds-body-sm` (14), не моно | под кадром, под числом |

Числа (`CaseNumbers`, `CaseImpact`) — `ds-display-5xl`, `tabular-nums`; это типографика итога, пятым уровнем текста не считаются. Название на обложке и в `CaseNext` — display, тоже вне четырёх уровней.

**Сетка на ≥ `bp-lg`:** метка — колонки 1–3, тезис и абзац — 4–10 с мерой нового токена `measure-case` → 600 px (≈ 65 знаков при 18 px, правило 9). Визуал — во всю ширину контейнера 1–12, шире текста. Карусель выходит за правый край контейнера до края окна.

**Вертикаль — только шкала ритма:**
метка →`flow-pair`→ тезис →`flow-node`→ абзац →`flow-group` (48)→ визуал →`flow-pair`→ подпись →`flow-block`→ следующий модуль блока →`section-gap`→ следующий блок. `flow-group` перед визуалом закрывает правило 7 («воздух ≥ 48»).

## 8. Модули подробно

**`CaseFacts`** — первая строка листа. ≥ `bp-lg` в одну строку до 6 колонок, `bp-md` — 3 колонки, ниже — 2. Метка `ds-meta-xs`, значение `ds-body-sm`. Ссылка на прототип — `TextLink inline external`, как сейчас в шапке.

**`CaseNumbers`** — числа в ряд, между ними стрелка `→` цветом `text-muted`; под числом подпись ≤ 12 слов. Ниже `bp-md` — столбиком, стрелка `↓`. Значение — строка как есть (`1 770`, `2,4 h`); `count` этапа 3 разбирает число из строки и досчитывает, без JS число стоит сразу.

**`CaseCallout`** — элемент крупно на плашке; на нём кружки-номера по координатам `x, y` в процентах кадра. Справа список номеров с текстом (≤ 12 слов каждый), от кружка к списку — тонкая линия `data-motion="draw"`. `tone=note` — номер ink (`callout-mark` → `gray-900`, как номер экрана в схемах); `tone=issue` (блок 04, «было») — номер красный (`callout-issue` → `error-500`, белая цифра 6.5:1). Ниже `bp-md` линий нет: номера на кадре, список под плашкой.

**`CaseArtifact`** — `CasePlate` + `Diagram` + подпись. Прокрутка схемы на 390 — уже в `Diagram`, плашка её не ломает.

**`CaseCarousel`** — нативная лента `scroll-snap-type: x mandatory`. Слайд — плашка шириной 78 % контейнера на ≥ `bp-md` (видно ≈ 15 % следующего), 88 % ниже. Кнопки «назад / вперёд» — круги 48 px справа над лентой, листают на слайд; без JS скрыты, лента листается свайпом, колесом с Shift и клавиатурой (лента фокусируемая, `aria-label`). Подпись под каждым слайдом. Счётчик `2 / 5` моно.

**`CaseSteps`** — на ≥ `bp-lg` две колонки: шаги слева (номер, тезис, абзац ≤ 30 слов), экран справа. Механика без JS: каждый шаг — строка «текст + экран», экран в строке `position: sticky` по центру окна, строка высотой не меньше окна. Пока читаешь шаг, его экран стоит; следующая строка приходит со своим экраном. `pin-swap` этапа 3 заменяет смену строки плавной сменой кадра в одной точке и добавляет точки прогресса. Ниже `bp-lg` — список: текст, под ним кадр.

**`CaseImpact`** — три карточки в ряд (`border-default`, `radius-lg`, поле `space-8`), крупная строка `ds-display-5xl` + подпись. Цитата — `ds-heading-2xl` с атрибуцией `ds-meta-xs`, только настоящая. Цена решения — метка + одна строка `ds-body-lg`. Ниже `bp-md` карточки столбиком.

**`CaseNext`** — блок во всю ширину окна на `surface-cover-<theme>` следующего кейса. Метка `Next case`, под ней название бегущей строкой `ds-display-7xl` (дубли строки `aria-hidden`). Весь блок — одна ссылка `<a>` с `.ds-pressable`; без JS и при `reduce` название стоит, переход — обычной ссылкой. Ниже — мелкая ссылка на прототип (`TextLink`, вне большой ссылки, чтобы не вкладывать). Раскрытие обложки следующего кейса через View Transitions — этап 3.

## 10. Разметка для `harmony-check`

Компоненты ставят атрибут `data-h`, скрипт читает только его — проверка не зависит от классов вёрстки.

| `data-h` | На чём | Проверка |
|---|---|---|
| `case` | корень страницы кейса (на `/kit` — корень демо-кейса) | ≤ 450 слов во всех текстовых `data-h` внутри |
| `plate` | `CasePlate` | поля верх/низ и лево/право — разница ≤ 2 px; ни один потомок не выходит за границы без `-bleed` (содержимое прокручиваемых контейнеров не считается) |
| `thesis` | тезис | нет строк из одного слова |
| `para` | абзац | ≤ 35 слов |
| `caption` | подпись кадра, числа, выноски | ≤ 12 слов |
| — | все `img` внутри `case` по порядку | соседние с одинаковым SHA-1 файла — ошибка |

`scripts/harmony-check.mjs` — Playwright на 1440 / 1024 / 390 по списку адресов (по умолчанию `/kit`), отчёт таблицей, код выхода ≠ 0 при нарушении. Команда `npm run check:harmony`.

### Финальное поведение Art direction

Focus использует светлую surface-plate вокруг тёмных реальных материалов; отдельная трасса сохраняет тёмную плашку. Это осмысленная смена поля, допускаемая новой постановкой, вместо последовательности почти чёрных прямоугольников. Визуальный центр и верх текста устойчивы; ширина/пропорция материала меняется. На mobile detail desktopOnly пропущен, поскольку narrow workspace уже содержит ту же переписку. Нумерация остаётся 01 / 02 / 03, в desktop второй довод имеет два кадра 02.

Back создаёт focus без вступительного каскада и сохраняет scrollY. При live reduce/resize сохраняется материал; после снятия pin выполняется конечный пересчёт в течение .18 с. Любой жест чтения отменяет отложенную коррекцию. Высоты от 820, ширины от 1024; короткий desktop читает нативную последовательность целых материалов. Хореография, cleanup и параметры централизованы, wheel не перехватывается.
