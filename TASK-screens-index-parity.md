# Разводные страницы прототипов — единый контракт

**Статус:** поставлена 2026-08-31. Источник правды по виду индекса экранов во всех
четырёх кейсовых прототипах.
**Решение об объёме:** структура, формулировки и анатомия карточки приводятся к
одному контракту; живые превью добавляются в B2B и Agent Ops. Решение владельца.

---

## 1. Задача

`/app` (или `/`) каждого прототипа — первое, что видит смотрящий кейс. Сейчас
четыре таких страницы устроены по-разному, и это читается как четыре разных
автора, а не как одна системная привычка.

| | Vet Clinic OS | B2B Partner Portal | Agent Ops Console | Pawly |
|---|---|---|---|---|
| Eyebrow | `VET CLINIC OS PREVIEW · APPLICATION · 13 LIVE SCREENS` | `B2B PROCUREMENT` | нет | `APPLICATION · 17 FRAMES` |
| H1 | Product screens | Screens | Agent Ops Console — screens | Product screens |
| Счётчики | в eyebrow | в подзаголовке | бейджами | в eyebrow |
| Действия | landing, DS | walk demo, DS showcase, reset | **в футере**, плюс мёртвый `localhost:6006` | landing, reset |
| Карточка | превью + node + размер | текст + стрелка | текст в `Panel` | превью + node |
| Группировка | плоско | 7 секций | плоско | плоско |

### Что НЕ меняется

Палитра, типографика, радиусы, тени, движение и компонентная база каждого
прототипа. Тёмный остаётся тёмным. Приводится к одному только **контракт
страницы** — порядок блоков, формулировки и анатомия карточки.

## 2. Контракт страницы

### 2.1 Порядок блоков

1. **Шапка**
2. **Строка статуса** — необязательная, только там, где состояние сессии есть в продукте
3. **Сетка карточек** — с группировкой, только если реестр объявляет группы
4. Футера нет

### 2.2 Шапка

| Слот | Формат | Обязателен |
|---|---|---|
| eyebrow | `<ПРОДУКТ> · APPLICATION · <N> SCREENS`, моно, капс | да |
| h1 | `Product screens` — ровно эти два слова во всех четырёх | да |
| lede | одно предложение: что это · из чего собрано · что со состоянием | да |
| actions | фиксированный порядок, см. ниже | да |

Eyebrow добавляет ` · <M> STATES`, если проект выносит состояния прототипа
отдельными плитками (это только B2B).

**Порядок действий фиксирован:** `View landing` · `Design system` ·
`Reset demo data` · [специфичное для проекта]. Отсутствующее просто
пропускается, порядок оставшихся не меняется.

| | View landing | Design system | Reset demo data | Extra |
|---|---|---|---|---|
| Vet Clinic OS | `/landing` | `/showcase` | в панели данных | — |
| Pawly | `/landing` | `/showcase` | есть | — |
| B2B Partner Portal | нет лендинга | `/showcase` | есть | `Walk the demo path` |
| Agent Ops Console | нет лендинга | `/showcase` | есть | — |

**Витрина Pawly заведена.** `src/Showcase.tsx` был собран целиком, но лежал вне
роутера и был написан по-русски, тогда как весь остальной прототип английский
с отдельным слоем локализации. Витрина переведена на английский, русские
формулировки перенесены в `src/i18n/RussianLocalization.tsx` (79 новых фраз),
`/showcase` заведён в `App.tsx` через `lazy` — страница поднимает все 33
компонента разом и открывается редко.

Имена компонентов ДС при переводе не трогаются: `Button`, `Icon`, `primary`,
`ghost`, `pressed` — это словарь системы, одинаковый в Figma, коде и Storybook.
Пословный запас держал `icon` и `button` для интерфейсных строк и превращал
заголовок раздела «Icon» в «Иконная», поэтому в `translate()` добавлен набор
`DS_NAMES`, который выводит эти имена из-под пословной подстановки.

**Возврат из витрины.** У Vet ссылка «All screens» в шапке витрины была,
у Pawly и Agent Ops витрина была тупиком — выйти можно было только кнопкой
браузера. Ссылка с той же формулировкой добавлена в оба. У B2B витрина живёт
внутри `AppShell`, и выход даёт навигация оболочки.

**Сброс данных у Vet.** Кнопка в панели `PrototypePanel` называлась `Reset data`
и переименована в `Reset demo data` — одна формулировка на все четыре прототипа.
Сама панель оставлена на месте: она сквозная и отдаётся не только индексу, но и
маршрутам вьюера, где переключение режимов Default / Offline / Empty и нужно.
Перенести её только на индексе значило бы сломать её собственную консистентность.

**Разводная страница Pawly `/`.** Ссылка «Pawly preview» из шапки индекса снята:
портфолио ведёт прямо на `/app`, и хаб посетителю кейса не показывается. Сам
маршрут остался — так же, как в Vet, где хаб был удалён раньше и лендинг с
витриной достижимы только с индекса.

### 2.3 Карточка

Одна анатомия во всех четырёх:

```
превью        живой экран, отмасштабирован, кадрирован фиксированной высотой
node          Figma node ID, моно, приглушённый
h2 + бейдж    имя экрана; бейдж справа, только если экран его требует
описание      одна строка
route         путь, моноширинный
```

Правила:

- **вся карточка — одна ссылка.** Превью `inert` и `aria-hidden`, доступное
  имя даёт заголовок;
- **превью кадрируется фиксированной высотой**, одной на прототип, обрезка
  сверху. Разная высота карточек в ряду — то, что читается как несобранность;
- **размер кадра в подписи не печатается.** У Vet он совпадал на 11 карточках
  из 13, у B2B высота артборда вообще не зафиксирована (`fixed width × hug
  height`). Размер живёт во вьюере экрана, где он что-то значит;
- **node — единственная мета-строка.** Экран без макета печатает
  `prototype-only` — конвенция уже заведена в Vet.

### 2.4 Бейджи

Бейдж на карточке — только если он несёт факт, которого нет в описании:

| Проект | Бейдж | Смысл |
|---|---|---|
| B2B | `Prototype state` | плитка не базовый экран, а вынесенное состояние |
| Agent Ops | `No access` | текущая роль этот экран не видит |

Бейдж `Live` у Agent Ops снимается: он стоял на каждой карточке и не различал
ничего.

## 3. Живые превью в B2B и Agent Ops

Экраны обоих проектов рендерят свой шелл сами (`AppShell` в B2B,
`AppSideNav` + `AppTopStrip` в Agent Ops), поэтому монтируются вне маршрута.
Две вещи, которые ломаются при монтировании двух десятков экранов сразу:

**1. Глобальные слушатели.** `document.addEventListener('keydown')` в
`ReviewQueue`, `RunDetail`, `Correction`, `ConsequencePreview`,
`KeyboardCheatsheet`, `RejectWithReason` (Agent Ops) и
`window.addEventListener('keydown')` в `ResolutionCenter` (B2B). Смонтированные
превью навесили бы их по разу на экран, и клавиша на индексе срабатывала бы
двадцать раз.

Решение: контекст `PreviewContext`. Экран внутри превью читает `useIsPreview()`
и выходит из эффекта первой строкой. Правка точечная — только там, где эффект
вешает слушатель на `document` или `window`.

**2. Вес DOM.** 26 десктопных экранов B2B с таблицами — это дорого на первую
отрисовку. Превью монтируется лениво, по `IntersectionObserver` с запасом в
один экран прокрутки; до монтирования в кадре стоит пустая поверхность той же
высоты, поэтому сетка не прыгает.

Vet и Pawly ленивого монтирования не получают: 13 и 17 экранов работают как
есть, и трогать рабочий код без причины незачем.

## 4. Порядок работ

| # | Проект | Что делается |
|---|---|---|
| 1 | Vet Clinic OS | эталон: eyebrow, снятие размера с мета-строки |
| 2 | Pawly | шапка на общую сетку, фиксированный кадр превью, хаб-ссылка снята, витрина переведена и заведена в роутер |
| 3 | Agent Ops Console | node ID в реестр, шапка, превью, футер наверх, `localhost` вон |

Каждый проект закрывается своим `typecheck` и `build`.
