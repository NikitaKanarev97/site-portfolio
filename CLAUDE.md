# Site-portfolio

Персональный сайт-портфолио продуктового дизайнера и Webflow-разработчика. Исходное ТЗ — `PROJECT.md`, оно источник правды для всех артефактов.

Порядок работ — `PLAYBOOK-site-portfolio.md`: проектная редакция общего плана «Продукт с нуля» под code-first без Figma. Что сделано, что осталось, в какой последовательности и почему шаги общего плана отменены — там.

## Артефакты проекта

| Папка | Что внутри |
|---|---|
| `outputs/` | бриф, ресёрч, персоны, приоритизация, PRD |
| `ia/` | инвентарь экранов, sitemap, user flows, wireframes |
| `ds/` | дизайн-система |
| `audit/` | UX-аудит |
| `src/` | кодовый слой: Astro-проект, компоненты, зеркала ДС (`README.md`) |

## Дизайн-система

В проекте поставлена дизайн-система. Все правила работы с интерфейсом — в `ds/CONTRACT.md`. При любых задачах, связанных с дизайном экранов, секций, компонентов:

1. Прочитай `ds/CONTRACT.md` целиком.
2. Прочитай `ds/foundation.md` и `ds/components.md` для текущего состояния токенов и каталога.
3. Действуй строго по правилам контракта.

**Экраны.** Финальные экраны собираются боевыми маршрутами в `src/pages/`, не песочницей. Composition map каждого — `ds/screens/<name>.md`, апрув карты идёт до вёрстки. Тексты живут в `src/copy/`, отдельно от композиции.

**Зеркала ДС в коде.** `ds/tokens.css` → `src/styles/tokens.css`, `ds/motion.js` → `src/scripts/motion.js` — побайтово. Правка идёт в `ds/`, копия обновляется тем же коммитом. Компоненты — `src/components/*.astro`, анимаций не пишут: объявляют движение атрибутом `data-motion`, хореография в `src/scripts/animations.js`.

Носитель ДС — код, не Figma. Источник правды по токенам — `ds/tokens.css`, по движению — `ds/motion.js`. Figma в проекте не используется; при возврате к ней она становится зеркалом кода, а не источником.
