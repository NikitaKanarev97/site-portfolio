# Site-portfolio

Персональный сайт-портфолио продуктового дизайнера и Webflow-разработчика. Исходное ТЗ — `PROJECT.md`; по направлению работ его перекрывает `DIRECTION-2026-11.md` (ниже).

## Действующий курс — с 18.11.2026 (читать первым)

После ревью тимлида 18.11.2026 направление работ задаёт **`DIRECTION-2026-11.md`**: диагноз AI-slop, принцип «одна система портфолио — три самостоятельных визуальных языка продуктов», процесс с арт-дирекцией до ДС, стоп-лист AI-умолчаний, тест подмены, состав из трёх кейсов, позиционирование «дизайнер, который доводит до кода». Порядок работ — **`PLAN-CHATS.md`** (этапы 0–9, промпт на каждый чат). По направлению работ (стратегия, состав, процесс, визуальные принципы, приёмка) `DIRECTION-2026-11.md` выигрывает у старых проектных документов, включая `PROJECT.md`, `ds/`, `tasks/`, `research/`. Технические инварианты (`ds/CONTRACT.md`, зеркала, доступность, сборка), `CONTENT-RULES.md` и ограничения конфиденциальности/NDA он не ослабляет; при конфликте — стоп и вопрос владельцу. Прежний план — архив `PLAN-CHATS-2026-10.md`, его этапы не запускать. Решения курса пересматриваются только прямым словом владельца — с датой, в самом `DIRECTION-2026-11.md`.

27.11.2026 владелец уточнил цель (Portfolio-first): три сильно рассказанные дизайнерские истории вместо редизайна всех маршрутов. Предложенная корректировка плана — `audit/portfolio-first-strategy/REPORT.md`, **на независимом ревью**, до решения владельца не применять.

Репозиторий на GitHub публичный: материалы DSSL без скрытия, реквизиты, цены и имена сотрудников в него не кладутся (они в `D:\Design\Cases\Case\`). Маскирование и переработка не равны разрешению на публикацию (DIRECTION, 7.1).

## Дизайн-система

В проекте поставлена дизайн-система. Все правила работы с интерфейсом — в `ds/CONTRACT.md`. При любых задачах, связанных с дизайном экранов, секций, компонентов:

1. Прочитай `ds/CONTRACT.md` целиком.
2. Прочитай `ds/foundation.md` и `ds/components.md` для текущего состояния токенов и каталога.
3. Действуй строго по правилам контракта.

**Экраны.** Финальные экраны собираются боевыми маршрутами в `src/pages/`, не песочницей. Composition map каждого — `ds/screens/<name>.md`, апрув карты идёт до вёрстки. Тексты живут в `src/copy/`, отдельно от композиции.

**Зеркала ДС в коде.** `ds/tokens.css` → `src/styles/tokens.css`, `ds/motion.js` → `src/scripts/motion.js` — побайтово. Правка идёт в `ds/`, копия обновляется тем же коммитом. Компоненты — `src/components/*.astro`, анимаций не пишут: объявляют движение атрибутом `data-motion`, хореография в `src/scripts/animations.js`.

Носитель ДС — код, не Figma. Источник правды по токенам — `ds/tokens.css`, по движению — `ds/motion.js`. Figma в проекте не используется; при возврате к ней она становится зеркалом кода, а не источником.
