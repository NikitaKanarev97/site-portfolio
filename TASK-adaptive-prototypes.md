# Адаптив прототипов портфолио — глобальная задача

**Статус:** поставлена 2026-08-28. Источник правды по объёму и порядку работ.
**Решение об объёме:** полный адаптив всех экранов, не заглушка. Решение владельца.

---

## 1. Задача

Три прототипа кейсов портфолио открываются с телефона сломанными. Нужно сделать
их полноценно адаптивными на всём диапазоне ширин — от 360 px до 1440 px и выше,
включая промежуточные: планшет, сжатое вдвое окно браузера, узкий ноутбук.

| Прототип | Репозиторий | Прод | Экранов |
|---|---|---|---|
| Agent Ops Console | `d:\Claude-projects\Agent-ops-console` | agent-ops-console.vercel.app | 19 |
| B2B Partner Portal | `d:\Claude-projects\b2b-dssl` | b2b-partner-portal-five.vercel.app | ~17 + индекс |
| Vet Clinic OS | `d:\Claude-projects\Veterinary-clinic` | veterinary-clinic-gules.vercel.app | ~14 + лендинг и индекс |

Pawly (`d:\Claude-projects\PETS-walking`) в задачу не входит: он mobile-first
и на телефоне работает.

### Почему это нужно

Половина смотрящих портфолио открывает ссылку с телефона. Сейчас все три
объявляют `<meta name="viewport" content="width=device-width">` — то есть
обещают браузеру, что макет умеет в 375 px, — и не умеют. Результат хуже, чем
если бы адаптива не было вовсе: браузер не масштабирует страницу, а ломает её.

### Что считается сделанным

На ширинах 360, 390, 768, 1024, 1280, 1440 px каждый экран каждого прототипа:

1. не даёт горизонтальной прокрутки документа;
2. показывает все свои данные и действия — ничего не обрезано и не выкинуто;
3. держит цели нажатия не меньше 44×44 px;
4. проходит `typecheck` и `build` проекта.

## 2. Контракт адаптива (общий для трёх проектов)

Этот раздел копируется в `ds/` каждого проекта на нулевом этапе, и дальше все
чаты работают по нему. Числа одни на три проекта, имена токенов — по конвенции
конкретной дизайн-системы.

### 2.1 Шкала брейкпоинтов

| Токен | Ширина | Что это |
|---|---|---|
| `bp-xs` | 360 px | нижняя граница поддержки, телефон |
| `bp-sm` | 480 px | крупный телефон |
| `bp-md` | 768 px | планшет книжный, сжатое окно |
| `bp-lg` | 1024 px | планшет альбомный, узкий ноутбук |
| `bp-xl` | 1280 px | десктоп |
| `bp-2xl` | 1440 px | опорная ширина исходных макетов |

**Mobile-first.** База пишется без media query и работает на 360. Все правила
надстраиваются через `min-width`. Существующие `max-width`-правила (70rem,
75rem, 72rem, 960px, 720px, 640px) переписываются на эту шкалу — сейчас они
означают «сломанный десктоп», а не «планшет».

Ниже 360 px гарантий нет. Выше 1440 px макет не растягивается бесконечно:
контент держит свою меру и центрируется.

### 2.2 Каталог превращений

Словарь решений. Экранный чат не изобретает своё, а берёт отсюда. Если нужного
превращения нет — оно дописывается в ДС проекта, а не в отдельный экран.

| Что | До `bp-md` | `bp-md` — `bp-lg` | От `bp-lg` |
|---|---|---|---|
| Боковая навигация | выдвижной drawer по бургеру: оверлей, ловушка фокуса, Escape | drawer или узкий рельс с иконками | постоянный сайдбар как сейчас |
| Плотная таблица | карточки-строки: заголовок, пары «поле — значение», действия внизу карточки | таблица со скроллом внутри своего контейнера, первая колонка залипшая | таблица как сейчас |
| Сетка N колонок | одна колонка, порядок = приоритет чтения | 2 колонки | N колонок |
| Мастер-деталь | два состояния одного экрана: список → деталь с кнопкой назад | список сверху, деталь снизу, либо 40/60 | как сейчас |
| Модальное окно | лист снизу на всю ширину, максимум 90vh, внутренняя прокрутка | центрированное окно | как сейчас |
| Панель фильтров | лист снизу «Фильтры», число активных на кнопке | сворачиваемая панель | как сейчас |
| Ряд действий | вертикальный стек на всю ширину, главное действие первым | ряд с переносом | ряд как сейчас |
| Ховер-подсказка | видимое состояние или раскрытие по нажатию | как на десктопе | как сейчас |
| Клавиатурные подсказки | скрыты — клавиатуры нет | видимы | видимы |

### 2.3 Жёсткие правила

- **Ничего не выкидывать.** Колонка таблицы, спрятанная на мобильном без другого
  пути к её данным, — потеря функциональности, а не адаптив. Данные переезжают
  в карточку, в раскрытие или в детальный экран.
- **Ни одной фиксированной ширины в пикселях** на уровне layout. `width: 240px`
  у сайдбара и `min-width: 62rem` у экрана — то, что чинится в первую очередь.
- **Ховер только под `@media (hover: hover)`.** На тач-устройстве отклик даёт
  `:active`. Состояние, существующее только в ховере, с телефона недоступно.
- **`100vh` не использовать** — на мобильных браузерах он врёт из-за адресной
  строки. Только `100dvh` / `min-h-dvh`.
- **Прокрутка внутри контейнера, не документа.** Широкое (таблица, диаграмма,
  таймлайн) прокручивается в своём `overflow-x: auto`; `body` не прокручивается
  горизонтально никогда.
- **Порядок в DOM = порядок чтения.** Перестановка блоков через `order` в grid
  ломает клавиатурную навигацию — переставлять в разметке.
- **Движение и `prefers-reduced-motion`** сохраняются как есть; новых анимаций
  адаптив не приносит.

### 2.4 Что не трогаем

- Мок-данные, тексты, локализацию (`i18n`), маршруты и их адреса.
- Продуктовые решения: какие экраны есть, что на них происходит, какие роли.
- Токены цвета, типографики и пространства — адаптив добавляет только
  токены брейкпоинтов.
- Storybook-матрицы компонентов не должны сломаться. Если у компонента
  появилось адаптивное поведение — оно описывается в `ds/components.md`
  по правилам `ds/CONTRACT.md` проекта.

## 4. Шаблон промпта для чата

Каждый новый чат открывается в каталоге своего проекта и получает текст ниже
с подставленными значениями.

```
Проект: <путь к репозиторию>
Задача: адаптив прототипа, этап <A3 / B1 / V0 ...>.

Общая задача и контракт адаптива:
d:\Claude-projects\Site-portfolio\TASK-adaptive-prototypes.md
Прочитай его целиком перед началом. Раздел 2 обязателен, раздел 3 определяет
границы этого этапа.

Также прочитай ds/CONTRACT.md этого проекта и действуй по его правилам:
дизайн-система здесь источник правды, экран её не обходит.

Объём этого этапа — ровно то, что перечислено в строке <шифр> раздела 3.
За его пределы не выходи: соседние экраны чинит соседний чат.

Готово, когда:
- npm run typecheck зелёный
- npm run build зелёный
- <скрипты приёмки проекта> зелёные
- каждый экран этапа проверен на 360, 390, 768, 1024, 1280, 1440
- нет горизонтальной прокрутки документа ни на одной из ширин
- все данные и действия доступны на 360 — ничего не выкинуто
- цели нажатия не меньше 44×44
- ds/components.md обновлён, если у компонента появилось адаптивное поведение

В конце: краткий отчёт — что изменено, какие превращения из каталога раздела
2.2 применены, что осталось спорным для следующего этапа.
```

Для нулевых этапов последний абзац заменяется на: «в конце — инвентарь:
таблица по всем экранам проекта, что ломается на 360 и на 768 и какое
превращение из каталога раздела 2.2 к нему применимо».

## 5. Приёмка проекта и выкладка

После шестого чата проекта:

1. `npm run build` и локальный `npm run preview` — прогон всех маршрутов
   на шести ширинах в DevTools.
2. Проверить обе локали там, где они есть (`/ru` в b2b и в Vet Clinic).
3. Задеплоить на Vercel.
4. Открыть прод с реального телефона, не только в эмуляции DevTools: адресная
   строка, безопасные зоны, инерция прокрутки и `dvh` ведут себя иначе,
   чем в эмуляторе.

## 6. Хвост в портфолио

После того как все три прототипа адаптивны, в `Site-portfolio` остаётся мелкая
задача, к трём проектам не относящаяся:

- `src/components/MediaZoom.astro` — на мобильном увеличение не увеличивает:
  `max-width: 100%; object-fit: contain` вписывает кадр в те же ~343 px, что
  и в колонке. Нужен pan/pinch внутри диалога.
- `srcMobile` в `MediaFrame.astro` построен и не использован ни в одном кейсе —
  можно задать мобильные кадрирования для плотных экранов.

Это отдельный чат, последний по порядку.
