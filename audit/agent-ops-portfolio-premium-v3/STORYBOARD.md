# Reading storyboard

Hero: name + proposition + sole designer / accepted prototype, then genuine approval. Historical problem: strong statement plus source-labelled financial consequence. Operating model: editorial reconstruction of documented logic, explicitly not an original workshop artifact. Reviewer sees commitments and causes; Shift Lead authorizes financial execution; Policy Owner bounds source changes.

Investigation: queue → separately identified run example, evidence and verdict. Financial checkpoint: one native approval remains whole while three outside-UI editorial stages explain request, billing/message consequences and the final human boundary. There is no pretend Approve button in the portfolio. On narrow screens the same three explanations precede the whole mobile approval.

Policy: originating cause → scoped draft → bounded approval → applied v5 → agent confirms v4 (unresolved). Quality: operating evidence and reversible capability authority. Process/outcome: research observations, design responses, verified test changes, then delivered / validated / accepted distinctions. Next-case navigation uses existing component.

Fast scan follows section titles and visual anchors; deeper reading uses body, stages, decisions and full-screen inspection. All product numbers in screenshots are synthetic. No testimonial or invented result counter.
