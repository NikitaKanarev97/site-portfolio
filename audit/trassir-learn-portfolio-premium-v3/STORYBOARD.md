# V3 proposed storyboard / EN + RU (pre-implementation)

This is **art direction**, not a replacement PRD. Final public copy must be checked against product and `CONTENT-RULES.md`. Visual sequence: genuine source → explicit model → true scenario states → grounded outcome; avoid mimicking Agent Ops' financial story.

## 0. HERO — the value is two routes, not a huge course catalog
- EN H1: `TRASSIR Learn`. Supporting statement: **One knowledge system. Two ways to learn.**
- RU H1: `TRASSIR Learn`. Supporting statement: **Одна база знаний. Два пути к результату.**
- EN lead, short: `A field specialist needs an answer now. A learner needs a trustworthy route to completion. I redesigned how both reach the same technical knowledge—without counting a page view as progress.`
- RU lead: `Специалисту нужен ответ сейчас. Учащемуся — понятный путь до завершения программы. Я пересобрал оба сценария на общей базе знаний, не превращая просмотр страницы в зачёт.`
- Role facts high in hierarchy: `Product / UX/UI Designer · architecture, flows, UI system and interactive implementation · 2026 rework of DSSL/TRASSIR assignment`. Avoid unverified `sole designer at DSSL` claim. If user was sole designer of current rework, show truthful ownership as a first-person statement.
- Media: full real task-led Home (B1) as primary, authentic full ONVIF answer detail as secondary. Mobile must retain one complete legible proof and not hide the supporting evidence until after half the page. Keep native brand blue, not the agent's carbon scheme.

## 1. CONTEXT — a course list is not an answer
- EN heading: **A catalogue tells you what exists. Not what to do next.**
- RU: **Каталог показывает, что есть. Но не подсказывает следующий шаг.**
- One short explanation: archived catalogue led with courses and filters while real entry situations differ: a camera is missing over ONVIF, or a specialist must prepare an installation/handover.
- Proof: archival original RU-only crop (B9), small but readable source label; alongside two authentic journey prompts, not fabricated persona quotes.
- This is an *architectural comparison*, **not** measured user performance or an old-versus-new production release claim.

## 2. ARCHITECTURE — one content object; two different records
- EN heading: **One material can answer a question and belong to a programme.**
- RU: **Один материал решает задачу и входит в программу.**
- EN key rule: **Reading is not completion.** RU: **Прочитано — не значит завершено.**
- Main artifact: source-backed content diagram from `src/data/diagrams/learn/content-model.ts`, visible by default, with typed routes: job/search → material → history; programme → same model material → explicit unit completion → separate assessment attempt. One strong native reference screenshot and a small explicit action detail next to it.
- **Accuracy guard:** V2 reference screenshot is ONVIF and player is archive retention, so two screenshots **do not** depict the same content item. Use real equivalent states if found, or caption as representative contexts and illustrate identity only in the verified system model.
- Motion: optional one very restrained progressive highlight of diagram branches as reader scrolls; all nodes/links remain readable without JS or when reduced-motion.

## 3. TWO JOURNEYS — answers versus deliberate programmes
- EN heading: **Solve the immediate problem. Or commit to the whole job.**
- RU: **Найти решение сейчас. Или подготовиться ко всей работе.**
- Reference proof: meaningful visible ONVIF header (version and update), diagnostic sequence and linked programme.
- Learning proof: named `Commissioning TRASSIR OS at a site with up to 32 cameras` path, authentic curriculum and exam conditions; `3 / 11` fixture, current step and clearly visible `Complete and continue` native action.
- Composition: wide reference panel then an alternating quiet programme plate with one selected action detail; no fake progress, no full-page screenshots scaled to unreadable thumbnails.

## 4. PROGRESS — preserve the difference
- EN heading: **Opening resources grows knowledge history. Only completed steps grow the programme.**
- RU: **Просмотр пополняет историю. Программу продвигают завершённые шаги.**
- Real examples: learner `9 resources read / 3 of 11 units`; reader `3 resources read / no programme credit`.
- Visual: one large native panel as focal evidence; small, fully legible counterexample with a direct explanatory label, rather than equal-scale miniatures of two whole account screens.
- Business rule: data comes from different fields; no unified progress percentage.

## 5. ASSESSMENT — clear outcome and recovery
- EN heading: **An unsuccessful result should still lead somewhere useful.**
- RU: **Непройденный зачёт должен объяснять, что делать дальше.**
- First proof: `14 / 20` versus `16 / 20` pass threshold; genuine retry/cooldown, linked practice. Connect a whole wrong-answer card with preserved answer and source. Secondary contrast: `20 / 20`, same threshold, training document. Don't visually describe the two separately generated outcomes as the before/after of **one** attempt.
- No official credential or verified learner improvement claim.

## 6. OUTCOME — what the designer actually delivered
- EN heading: **A connected learning experience with honest boundaries.**
- RU: **Единый опыт обучения с понятными границами.**
- Three short substantiated outcomes: `Task-led entry and versioned answers`; `Separated reading and completion models`; `Recoverable, rule-based assessment states`.
- One named tradeoff: explicit completion action and independent progress records increase user effort but prevent ambiguity.
- Truthful check: UX rules/routes/states browser tested; direct specialist usability and subject-matter correctness not claimed as measured. Product/landing links in the matching language, existing next-case component.

## Reading and animation standards
- The top two screenfuls must answer product, real assignment origin, design authorship, user jobs and a meaningful interface example.
- Scan titles alone: catalogue problem → shared knowledge model → two paths → honest progress → meaningful result → design outcome.
- Full visible copy should feel editorial and crisp; don't add storybook-length process logs. Make visual evidence occupy more weight than paragraphs. Break up repeated full-width card rhythm with a diagram, contrast states and full-res zoom.
- Support EN/RU, contrast, 1440/1024/768/390/360/320; mobile should not simply stack two desktop plates one after the other for many screens.
- Motion must communicate a branch or progression, not decoration; no scrolljack, fake state transitions or heavy parallax. Static fallback must convey exactly the same logic.
