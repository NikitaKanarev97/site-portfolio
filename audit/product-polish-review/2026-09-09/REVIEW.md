# Проверка Product Polish · 9 сентября 2026

Обновлена [страница этапа 5 в Notion](https://app.notion.com/p/3d62eeb7cb4481329185ff0bdbcb81fb) и локальная [шпаргалка](../../../PLAYBOOK-product-upgrade.md). Основание — запрос объединить опыт лендинга Learn, основного Learn и Agent Ops. Код продуктов, медиа и настройки навыков этим проходом не менялись.

## Основной вывод

Версия Клода хорошо описывала визуальную доводку Agent Ops, но превращала ограничения одного прогона в универсальные правила. Для воспроизведения работы с Learn требовались также редактура, UX, сквозные состояния и доказательная упаковка кейса. В новой версии девять основных шагов и опциональный 08Б; большие группы могут занимать несколько чатов.

| Формальная зависимость от трёх навыков Claude | Самодостаточные промпты, навыки как помощь | В локальных версиях product-polish и prototype-i18n зашиты ограничения Agent Ops; они отсутствуют среди активных навыков Codex |
| Каждый baseline сразу получает V/C/R | Независимые статусы по виду доказательства и актуальной версии | REVIEW-METHOD Learn: PNG и код не подтверждают runtime |
| Повторный полный обход всей матрицы на каждом шаге | Реестр сохраняется, доказательства переиспользуются, новые проверки отвечают на вопросы | Уточнение пользователя о расходе токенов в USER-DIRECTION / REVIEW-METHOD |
| Запрет новых корневых причин в 03Б | Дедупликация общих причин и право добавлять подтверждённые новые | Поздний проход Agent Ops добавил находки; заранее фиксированная модель причин скрывает новое |
| Жёсткий пилот из трёх конкретных типов экранов | 2–3 характерных экрана/части сценария с покрытием рисков | У Learn пилот — программа, история и результат; у лендинга другой состав |
| Поздняя группа может исчезнуть за «готово» | Проверка полноты аудита перед окончательным выбором пилота | STATE Agent Ops: 03B выполнен после первоначальной приёмки, расширены причины и носители |
| Общий токен в пилоте считается локальной правкой | Назвать и проверить других потребителей, ограничить распространение | Learn переносил изменения общей сетки, MaterialRow, AnswerOption и модели доступа |
| «Ноль P0» и закрытия с расхождением означают готовность | Критерии пути и объёма, отдельные статусы исправлено/принято с ограничением/непроверено | Agent Ops BACKLOG и STATE расходились; Learn ограничивает готовность демонстрацией |
| /ru и DOM-наложение обязательны; query ненадёжен | Существующая архитектура локали, язык в ссылках, проверка всей цепочки | LOCALIZATION.md Learn: путь /en и lang-query, статический рендеринг; Agent Ops использует /ru и DOM |
| Переснять всё на общей норме, менять только отдельные абзацы | Обновить нужные носители и доказательный рассказ, сохранить факты и архив | Learn проверял реальную роль, статус переработки, происхождение кадров и соответствие двух языков |
| Скрипт стирает каталог — переснять потерянное | Сначала проверить скрипт и снимать в отдельный каталог, затем заменять | HANDOFF Agent Ops описывает потерю соседних медиа при очистке каталога |
| Страница кейса проверена отдельно от демо | Путь карточка → кейс → лендинг/демо → действие, язык/F5/deep link | Финальная приёмка кейса Learn, reports/09.md |
| Разные состояния могут выглядеть как неполный перенос | Сопоставлять ту же задачу, состояние, данные, локаль и ширину | 09-practice-recheck.md: первоначальный вывод отменён после уточнения пользователя |

Сохранены сильные части исходника: два взгляда (пользователь/заказчик), доказательства, системные причины, визуальные референсы, пилот до переноса, работа через ДС, волны по зависимостям, возврат регрессий под прежним ID, обновление кейса.

Конкретные цифры контраста, число кадров, названия токенов, SVG как обязательный инструмент, две темы и фиксированные три ширины убраны из универсальной инструкции. Это свойства и решения конкретных проектов, а не общая планка качества.
