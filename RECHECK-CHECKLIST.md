# Общий свод проверок перепроверки адаптива

Читается вместе с промптом своего проекта: `RECHECK-A.md`, `RECHECK-B.md`,
`RECHECK-V.md`. Контракт адаптива — раздел 2 файла `TASK-adaptive-prototypes.md`.
Этот файл описывает **что** проверять и **как мерить**, промпт проекта — **где**.

---

## 0. Правила работы

### 0.1 Состояние деревьев

Во всех трёх проектах лежит большой пакет **незакоммиченных** правок. Это и есть
проверяемый результат. Отметки PASS в существующих `artifacts/adaptive-qa/**` —
карта покрытия, а не доказательство: их делала та же сессия, что вносила правки.

**Запрещено:** `git reset`, `git checkout --`, `git restore`, `git stash`,
`git clean`, удаление untracked-файлов, перезапись существующих
`artifacts/adaptive-qa/**`, начало проверки от `HEAD` вместо рабочего дерева.

**Единственная разрешённая мутация git** — создание baseline-worktree по п. 1.2.
Она не трогает рабочее дерево и снимается `git worktree remove` в конце.

Всё временное — только в `.tmp/claude-recheck/`. Результаты перепроверки — только
в `artifacts/adaptive-recheck/`.

### 0.2 Две фазы

**Фаза 1 — аудит, строго read-only.** Ничего не чинишь. Финал фазы: файл
`artifacts/adaptive-recheck/findings.md` и краткий отчёт в чат. Остановка.

**Фаза 2 — починка.** Начинается только по явной команде пользователя, с
утверждённым списком. Правка идёт в источник по `ds/CONTRACT.md` проекта: если
поведение принадлежит компоненту — чинится компонент, а не экран. После каждой
правки — ретест затронутых маршрутов на всех шести ширинах и повторный прогон
обязательных команд проекта.

### 0.3 Дисциплина доказательства

Находка без воспроизведения — не находка. Каждый пункт отчёта несёт: абсолютный
путь и строку, маршрут, состояние, локаль, ширину, измеренные числа, шаги.
Обратное тоже верно: не снимай реальный дефект как «шум» без воспроизводимого
доказательства обратного.

## 1. Измерительный прогон

Второй комплект скриншотов не нужен: существующие PNG используются как визуальная
карта. Нужны свежие **измерения**. Харнесс пишется в `.tmp/claude-recheck/`,
на Playwright, Chromium. Вывод — JSON плюс компактная markdown-таблица.
Скриншот снимается только под подтверждённое расхождение.

### 1.1 Матрица

Ширины: **360, 390, 768, 1024, 1280, 1440**. Высота 900, плюс отдельный прогон
низкой высоты 360×640 для auth-экранов и оверлеев.
Локали: обе там, где они есть.
Состояния маршрутов: все, перечисленные в manifest проекта.
Эмуляция касания: прогон на телефонных ширинах идёт с `hasTouch: true`,
десктопные — без. Это влияет на `@media (hover: hover)` и обязано влиять.

### 1.2 Слой 1 — дельта отступов против исходника

```
git worktree add .tmp/claude-recheck/baseline HEAD
```

Рабочее дерево не затрагивается. `node_modules` в baseline не ставь заново:
сделай junction на существующий —
`cmd //c mklink /J .tmp\claude-recheck\baseline\node_modules <абсолютный путь>\node_modules`,
и только если junction не создался — `npm install` внутри baseline.
Собери baseline и подними его preview на соседнем порту.

По каждому маршруту на **1280 и 1440** снимай с обеих сборок для каждого
элемента с непустым боксом:
`padding-*`, `margin-*`, `gap`, `row-gap`, `column-gap`, `border-width`,
`min-height`, `height`, а также фактические зазоры между соседями по
`getBoundingClientRect`.

Сопоставление элементов между сборками — по устойчивому пути в DOM
(тег плюс индекс среди сиблингов, от корня маршрута), не по классам:
у CSS-модулей меняются хеши.

**Любая ненулевая дельта на 1280 и 1440 — находка по умолчанию**, пока не
доказано, что это осознанное решение, записанное в `ds/`. Десктоп адаптив
менять не должен был.

### 1.3 Слой 2 — принадлежность шкале на адаптивных ширинах

На 360/390/768/1024 значения обязаны отличаться от десктопа — здесь проверяется
не совпадение, а шкала. Собери из токенов проекта множество разрешённых значений
отступов и сверь с ним каждое computed-значение `padding` / `margin` / `gap`.

В отчёт идут:

- значения вне шкалы токенов;
- сырые `px` в layout-свойствах в диффе (`git diff` по `*.css`);
- схлопнутые в ноль зазоры между блоками, которые на десктопе разделены;
- удвоенные отступы: `margin` ребёнка поверх `gap` родителя;
- несимметричные боковые паддинги контейнера — левый не равен правому без причины;
- потерянный ритм у первого и последнего элемента списка или секции;
- вертикальный ритм вокруг контролов: если высота поля задана не паддингами, а
  фиксированной величиной, соседние отступы поедут по всему экрану — проверь
  расстояние «подпись → поле → подсказка» и «поле → следующий блок».

### 1.4 Слой 3 — прогон по состояниям контролов

Для **каждого** фокусируемого элемента на каждом маршруте пройди цепочку:
`покой → hover → focus-visible → active → ввод значения → blur → повторный фокус`.
Дополнительно, где применимо: `disabled`, `loading`, `readonly`, реально
невалидное значение.

На каждом шаге проверяй:

1. Цвет рамки и кольца при фокусе равен фокус-токену, **не** alert/danger-токену.
   Красная подсветка при простом клике в поле — дефект.
2. `aria-invalid` и любой флаг destructive не появляются от захода в поле, от
   выхода из пустого нетронутого поля и от первого введённого символа. Только по
   факту ошибки.
3. Красное состояние всегда сопровождается читаемой причиной. Красная рамка
   без текста — дефект.
4. Фокус-кольцо не обрезается родительским `overflow: hidden` и не выходит за
   край вьюпорта на 360.
5. Фокус не сдвигает раскладку: бокс соседей до и после фокуса совпадает.
   Кольцо, добавляющее высоту, — дефект.
6. Видимая коробка контрола и его hit-область совпадают: клик в 4 px внутрь от
   видимого края обязан попасть в контрол, клик в 8 px наружу — не обязан.
7. Цель нажатия ≥ 44×44 **в каждом состоянии**, а не только в покое.
8. `hover` живёт под `@media (hover: hover)`; на тач-прогоне отклик даёт
   `:active`, а состояний, доступных только по ховеру, нет.
9. `disabled` не получает фокус, но остаётся читаемым по контрасту.
10. Плейсхолдер не подменяет подпись: при заполненном поле видно, что это за поле.

### 1.5 Формат вывода харнесса

`artifacts/adaptive-recheck/measurements.json`:

```
{ "project": "...", "generatedAt": "...",
  "spacingDelta":  [ { "route","locale","width","domPath","prop","baseline","current","delta" } ],
  "spacingScale":  [ { "route","locale","width","domPath","prop","value","nearestToken","issue" } ],
  "controlStates": [ { "route","locale","width","control","step","check","expected","actual","pass" } ],
  "layout":        [ { "route","locale","width","check","value","pass" } ] }
```

## 2. Классы дефектов

Проверяется каждый блок. Пустой блок в отчёте означает «проверено, чисто», а не
«пропущено».

### A. Сборка и статика

- обязательные команды проекта зелёные, вывод приложен, не пересказан;
- `git diff --check` без ошибок пробелов;
- сборка без новых предупреждений, кроме известных и перечисленных в промпте;
- в диффе нет мёртвых импортов, осиротевших CSS-модулей, закомментированного кода;
- перевод строк не менялся массово: правка CRLF/LF во всём файле маскирует диф —
  если такое есть, скажи об этом отдельно.

### B. Реестр и маршрутизация

- реестр маршрутов, собранный из живого кода и индекса, совпадает с
  `artifacts/adaptive-qa/manifest.json`; расхождение по числу кадров объясняется;
- каждый маршрут из реестра открывается и не даёт fallback-заглушки;
- алиасы, редиректы и неизвестный маршрут ведут себя как задумано;
- deep-link с query-состоянием открывает нужное состояние **сразу**, а не после
  ручного клика — на 360 и 390 в том числе;
- переключение локали сохраняется при навигации по ссылкам, а не только по
  прямому URL;
- «назад» браузера возвращает предыдущее состояние, включая мобильный
  мастер-деталь и открытые оверлеи.

### C. Раскладка и адаптив

- `document.scrollWidth <= document.clientWidth` на каждой ширине;
- широкое скроллится внутри своего контейнера, `body` горизонтально — никогда;
- нет `100vh`, есть `100dvh`; safe-area учтена; низкая высота 360×640 не ломает
  auth и оверлеи; альбомная ориентация телефона проверена;
- нет фиксированных пиксельных ширин на уровне layout и `min-width`, отрезающих
  контент;
- ни одна колонка, ячейка или блок не схлопывается в 0 px;
- обрезка текста не теряет данные: если есть ellipsis — значение доступно иначе;
- длинные слова, адреса, артикулы и числа не рвут контейнер;
- порядок в DOM равен порядку чтения, перестановок через `order` нет;
- fixed и sticky элементы ничего не перекрывают — проверяется hit-тестом точки,
  а не на глаз: шапка, футер, панель действий, тост, панель прототипа;
- переходные раскладки 768 и 1024 — самостоятельные состояния, а не сжатый
  десктоп и не растянутый телефон;
- масштаб браузера 200% и увеличенный системный шрифт не дают горизонтальный
  скролл документа.

### D. Отступы

Полностью по пп. 1.2 и 1.3. В отчёте — отдельным разделом, с числами.

### E. Состояния контролов

Полностью по п. 1.4. В отчёте — отдельным разделом, с числами и цветами.

### F. Оверлеи

Для каждого drawer, modal, dialog, sheet, popover, select, тултипа, панели
подсказок и панели прототипа:

- первый фокус уходит внутрь и на осмысленный элемент;
- ловушка фокуса замкнута в обе стороны, Tab и Shift+Tab;
- Escape закрывает; клик по оверлею закрывает там, где так задумано;
- фокус возвращается на элемент, который открыл;
- фон получает `inert` или эквивалент и не читается скринридером;
- прокрутка body/root заблокирована, и **позиция прокрутки не прыгает** при
  открытии и закрытии;
- внутри оверлея своя прокрутка, содержимое не обрезано на 360 и на 360×640;
- оверлей закрывается или корректно перестраивается при смене ширины и при
  смене маршрута;
- повторное открытие даёт то же состояние, а не остатки прошлого.

### G. Клавиатура и доступность

- порядок Tab совпадает с порядком чтения, ловушек вне оверлеев нет;
- видимый фокус есть у каждого интерактивного элемента, включая ссылки в тексте,
  строки таблиц и карточки;
- иконочные кнопки имеют доступное имя; бургер несёт `aria-expanded` и
  `aria-controls`;
- заголовочная иерархия не сломана адаптивом;
- контраст текста и границ не упал ниже порога в мобильных вариантах;
- `prefers-reduced-motion` уважается, новых анимаций адаптив не принёс.

### H. Данные, логика, локализация

- прочитан дифф целиком: адаптив не изменил бизнес-логику, расчёты, форматирование,
  мок-данные, маршруты и тексты;
- на 360 доступны все данные и все действия, что и на 1440 — ничего не выкинуто
  и не спрятано без второго пути;
- числа, валюты, единицы, дозы, даты форматируются одинаково на всех ширинах;
- RU-строки длиннее EN на 20–30% и рвут ровно то, что на EN выглядит целым:
  кнопки, вкладки, заголовки, ячейки, подписи;
- паритет содержимого EN и RU: ни один блок не потерялся в одной из локалей;
- ключи i18n не потеряны, фолбэков на сырой ключ в интерфейсе нет.

### I. Консоль и рантайм

На каждом маршруте и после каждого сценария:

- ноль ошибок консоли, ноль необработанных промисов, ноль ошибок сети и 404;
- ноль предупреждений React: ключи списков, controlled/uncontrolled, вложенность
  тегов, обновление состояния при размонтировании;
- нет overlay ошибок фреймворка;
- шрифты и иконки грузятся, нет вспышки подмены на мобильном;
- нет заметного сдвига раскладки после загрузки.

### J. Дизайн-система и Storybook

- coverage-скрипт проекта зелёный, ни одна стори не сломана;
- у компонентов, получивших адаптивное поведение, оно описано в `ds/components.md`
  по правилам `ds/CONTRACT.md`;
- компонент не обходит токены ради экрана и не завёл собственных значений;
- зеркала ДС в коде не разошлись с `ds/`.

### K. Артефакты QA

- `artifacts/adaptive-qa/index.html` открывается через `file://`, фильтры и
  превью работают, относительные ссылки не битые;
- ссылки на доказательства из `findings.md` ведут на существующие файлы; если
  доказательство лежит во временной папке, которой уже нет, — фикс считается
  недоказанным и воспроизводится заново.

## 3. Формат отчёта фазы 1

`artifacts/adaptive-recheck/findings.md` и краткая версия в чат:

1. Таблица: блок A–K, вердикт, число находок.
2. **Подтверждённые дефекты**, по убыванию severity. Каждый: путь и строка,
   маршрут, состояние, локаль, ширина, измеренные числа, шаги воспроизведения,
   предполагаемая причина в коде.
3. **Дельта отступов** отдельным разделом: таблица «маршрут / элемент / свойство /
   было / стало / дельта», десктоп отдельно от адаптива.
4. **Состояния контролов** отдельным разделом: что именно и на каком шаге
   отработало не так.
5. **Расхождения** кода, живого реестра и `manifest.json`.
6. **Неблокирующий техдолг** и out-of-scope.
7. Вердикт: можно ли принимать проект, и что обязано быть исправлено до приёмки.

Ничего не чини. Остановись и жди команды на фазу 2.
