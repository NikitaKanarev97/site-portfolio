## 3. Правила — с этого дня

### Кропы и детали
1. **Не дублировать.** Увеличенная копия элемента поверх экрана, где этот элемент виден, запрещена. Деталь показывается отдельным кадром — крупно и с выносками (блок 08 схемы), либо не показывается.
2. **Резать только по границе смыслового блока:** карточка, панель, строка таблицы — целиком. Никогда посреди текста, колонки, кнопки, прогресс-бара.
3. **Ничего не режется краем плашки.** Выход за край — только сознательный, по одному правилу для всех кейсов (например, телефон выходит за низ плашки на фиксированные 48 px).
4. **Один масштаб на кадр.** В одном кадре не может быть одной и той же кнопки двух размеров.

### Отступы и ритм
5. **Плашка: поля из токенов, симметрично.** Верх = низ, лево = право; скриншот центрирован. Нижнее поле никогда не меньше верхнего.
6. **Вертикальный ритм из одной шкалы:** между модулями, между тезисом и абзацем, между кадром и подписью — фиксированные шаги токенов, одинаковые во всех кейсах.
7. **Воздух вокруг кадра** не меньше 48 px на десктопе; кадр не прилипает к тексту.

### Типографика
8. **Четыре уровня, не больше:** метка (моно, капитель, 12–13 px) · тезис (крупно, 32–48 px) · абзац (18–20 px) · подпись (14–15 px, обычный шрифт). Моноширинный — только метки и числа, не предложения.
9. **Ширина строки 45–70 знаков,** без висячих предлогов и одиночных слов в последней строке (`text-wrap: balance` для тезисов, `pretty` для абзацев); переносы проверяются на 1440, 1024, 390.
10. **Подпись — одна строка,** до 12 слов. Если не влезает — это не подпись, а абзац.

### Подача кадров
11. **Один стандарт съёмки:** десктоп 1440 × 900 при 2x, телефон 390 × 844 при 3x; кадр — экран целиком или блок целиком; без полос прокрутки, без подвала сайта, без панели плеера.
12. **Плашки по системе:** нейтральная светлая для экранов; цвет кейса — только на обложке и в переходе; тёмная — только для тёмного продукта (Agent Ops) и одинаковая во всех его кадрах.
13. **Не два одинаковых кадра подряд;** десктоп и телефон одного экрана — в одном кадре рядом, а не двумя кадрами.
14. **Компоненты — в формате библиотеки** (`ha-deep-dive.md` §4.4): набор в рамке, состояния столбиком, подписи; не сырая сетка.
15. **Мягкий, не технический вид:** тени и скругления из токенов, без цветных «подсветок» поверх скриншота, без растягивания элементов под край.
16. **Одна визуальная среда на страницу:** B2B-кадры и сочные картинки разведены по разделам (Webflow-сборки — отдельной секцией с отдельной подачей).

## 4. Как проверяем

- **Глазами:** перед приёмкой кейса — проход по этому списку, каждый пункт «да/нет» в отчёте этапа.
- **Скриптом** (сделать на этапе «Система модулей»): Playwright на 1440 / 1024 / 390 —
  - поля плашек: разница верх/низ и лево/право ≤ 2 px;
  - ни один дочерний элемент плашки не выходит за её границы без класса `-bleed`;
  - одинаковые картинки (по хэшу) не стоят подряд;
  - подписи ≤ 12 слов, абзацы ≤ 35 слов, кейс ≤ 450 слов;
  - нет строк из одного слова в тезисах.
- **Второе мнение:** готовый пилот показать Роберту (ADPList) или другому ментору до переноса на остальные кейсы.
