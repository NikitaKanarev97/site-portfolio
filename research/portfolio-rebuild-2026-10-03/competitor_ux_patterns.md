# Паттерны и перенос в текущую ДС

03.10.2026. Отбор строится по задаче зрителя: быстро понять работу и захотеть рассмотреть её.

## Общий стандарт выбранных страниц

Название и короткое обещание появляются до подробностей. Факты компактны. Основную площадь занимает материал работы. Следующая работа доступна без возвращения в каталог. Общий каркас сайта уступает внимание характеру проекта.

## Где способы расходятся

HA собирает каталог разных артефактов; Blinkov продаёт опыт через обзор; Victor строит визуальную последовательность; Dounar показывает причинную связь исследования и направления. Поэтому выбирать одного «донора на всё» недостаточно.

## Решения для нашего сайта

| Паттерн | Где | Польза | Ограничение |
|---|---|---|---|
| Большой реальный продуктовый кадр → крупная деталь | Каждый кейс | Видно и общее качество UI, и качество конкретного решения | Значимые действия и собственные поля панели сохраняются |
| Диагноз → предложение → реализованный экран | Portal; Learn | Исследование объясняет решение | Только подтверждённые исходные наблюдения |
| Карта владения → сценарий переходов | Portal | IA и flow отвечают на разные вопросы | Не показывать обе схемы с одинаковым содержанием |
| Рабочий материал + одна аннотация о выборе | Learn; Portal | Видно мышление автора | Не выгружать полный PRD или доску |
| Компоненты → состояния → экран применения | Portal; выборочно Learn/Pawly | ДС выглядит рабочим инструментом | Снимки реальных компонентов, а не стилизация стандартной кнопки |
| Материал, следующий слайд которого частично виден | Второстепенные артефакты | Понятно, что есть продолжение | Главный аргумент остаётся видимым без клика; кнопки подписаны |
| Одна сцена изменения с читаемой остановкой | Каждый кейс по необходимости | Движение направляет внимание | Статика рассказывает тот же смысл; pin не обязателен |
| Итог / доказательство / цена | Каждый кейс | Показывает результат и зрелость решения | Нет принудительных процентов или карточек с числом компонентов |
| Большая обложка следующей работы | Все кейсы | Продолжает просмотр | Порядок читается из реестра; автопереход от скролла не используется |

## Что корректируем в прежних правилах

Единый набор модулей сохраняется. Фиксированные десять секций, одинаковый состав артефактов и одинаковая режиссура перестают быть обязательными. Цветовое поле выбирается по продукту и смыслу; мы не чередуем светлое и тёмное ради количества смен. Построчное раскрытие не задерживает смысл. Число анимируется только при наличии проверенного значения и единицы.

Действующие технические правила остаются: токены ДС; `withMotionPreference()`; общий исполнитель движения; native scroll; отдельная мобильная подача; читаемые fallback; корректный Back. Пилотный checkpoint — одна из композиций, а не рецепт каждого кейса.
