# Site-portfolio — план работы по чатам (с 18.11.2026)

Переделка портфолио после ревью тимлида 18.11.2026: три кейса вместо пяти, у каждого продукта свой визуальный язык, новое позиционирование «дизайнер, который доводит до кода». **Что и почему решено — [DIRECTION-2026-11.md](DIRECTION-2026-11.md); этот файл — только порядок работ.** Каждый этап — отдельный чат. Промпт копируется целиком, правятся только места `<...>`.

Убрано против полной ветки «Продукт с нуля»: ресёрч рынка, персоны, бенчмарк (есть, ревью их перекрывает); Figma и UI-кит (решение владельца — рисуем в коде); wireframes (экраны есть, меняются стиль и плотность, не структура); финальная приёмка только агентами (её место занимает этап 6 с живым лидом).
Объединено: прототип и кейс Agent Ops — один чат; прототип и кейс Learn — один чат (шаблон отработан на пилоте).

## Общие правила для всех чатов

- Первым делом прочитать [DIRECTION-2026-11.md](DIRECTION-2026-11.md) целиком. Решения оттуда не пересматривать без прямого слова владельца.
- Стоп-лист AI-умолчаний (раздел 5 DIRECTION) проверяется на **каждом** экране, который чат создаёт или меняет. Нарушение — не закрытие этапа.
- Claude предлагает варианты и рекомендацию, выбор — за владельцем. Утверждать направления и экраны самому нельзя.
- Рисуем в коде, Figma не используется.
- Репозиторий Site-portfolio публичный. Материалы DSSL без скрытия, реквизиты, цены, имена сотрудников — только в `D:\Design\Cases\Case\`, в репозиторий не кладутся. Кадры из `Прод-2026-11/скрыто-NDA/` публиковать можно.
- Факты не выдумываем. Нет метрик — пишем, что есть (внедрение, приёмка, тесты), и где граница выводов. Даты сверять с памятью `owner-work-chronology` и разделом 8 DIRECTION.
- Тексты публичных страниц — по [CONTENT-RULES.md](CONTENT-RULES.md): без меток «концепт».
- Дизайн-система сайта — по `ds/CONTRACT.md`; зеркала `ds/` → `src/` обновляются тем же коммитом. ДС продуктов живут в их репозиториях.
- Закрывая этап: обновить статус в карте выше, записать выходы, коммит в репозитории, где шла работа.
